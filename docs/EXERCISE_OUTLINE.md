# EXERCISE_OUTLINE.md — 実践演習(practice)設計

`docs/CONTENT_OUTLINE.md`がレッスンの唯一の正であるのと同様に、このドキュメントは**実践演習(practice/)の唯一の正**とする仕様書です。演習ページを書く/直す際は、必ずこの一覧の仕様に従ってください。

## 演習の目的・書き方の方針

- レッスンは「1つの概念を、動くコード込みで説明する」もの。演習は逆に**完成コードを載せず**、設計仕様(処理仕様・期待する動作・利用する依存関係)だけを示し、学習者自身にコードを書かせる。
- 文章で「〜を作ってください」と指示するのではなく、要件を箇条書きの**仕様**として提示する(処理仕様/期待する動作/依存関係/ディレクトリ構造)。
- 各演習は、その実装に必要な概念を扱っているレッスンに**必ずリンク**する(「関連レッスン」セクション)。ex-01〜07は既存88レッスンの範囲内で全て賄えたため新規レッスン追加なしだったが、ex-08以降(プロジェクトトラック向け)は`docs/TRACK_OUTLINE.md`の新規レッスンを前提とする。新しい演習を追加する際、既存レッスンでカバーできない概念が必要になった場合は、レッスンを先に追加してからリンクすること。
- 必ず**ディレクトリ構造(ファイルツリー)**を明記し、どのファイルに何を書くかが一目でわかるようにする。
- 難易度は`docs/DESIGN_SYSTEM.md`のtierカラー・ラベル(🟢入門〜⚫上級)をそのまま流用し、5段階で表す(`window.TIER_INFO`を再利用)。

## ex-01: NPC受付システム(難易度1・🟢)

**概要**: 特定座標にNPCを配置し、ミニマップにBlipを表示、近くで受付コマンドを実行すると案内メッセージが出る。

**ディレクトリ構造**
```
ex01-reception/
├── fxmanifest.lua
└── client.lua
```

**処理仕様**
- resource起動時、固定座標にNPC(ped)を1体生成し、その場から動かないようにする。
- 同じ座標にBlipを表示し、名前とアイコンを設定する。
- `/reception`コマンドを登録する。
- コマンド実行時、プレイヤーとNPCの距離を計算し、一定距離(例: 3.0m)以内なら案内メッセージを、範囲外ならエラーメッセージをチャットに表示する。
- resource停止時にNPCを確実に削除する(`onResourceStop`)。

**期待する動作**
- サーバー起動直後、指定座標にNPCとBlipが表示されている。
- NPCから離れた状態で`/reception`を実行すると「近づいてください」等のメッセージが出る。
- NPCに近づいて`/reception`を実行すると案内メッセージが出る。
- resourceを`restart`してもNPCが重複生成されない。

**利用する依存関係**: なし(FiveM標準nativeのみ)。

**関連レッスン**: t2-02(NPCを配置する)/ t2-03(Blip/Markerを表示する)/ t2-04(コマンドを登録する)/ t1-05(デバッグの基本)

## ex-02: シンプルショップ(NUI+イベント)(難易度2・🟡)

**概要**: NUIで商品一覧を表示し、購入ボタンを押すとserver側で所持金(擬似的な変数でよい)を確認して購入処理を行う。DBは使わずメモリ上のテーブルで管理する。

**ディレクトリ構造**
```
ex02-shop/
├── fxmanifest.lua
├── client.lua
├── server.lua
└── ui/
    ├── index.html
    ├── style.css
    └── script.js
```

**処理仕様**
- server.luaに商品リスト(name, label, price)をテーブルで定義する。
- server.luaにプレイヤーごとの所持金を管理する簡易テーブル(初期値1000等)を用意する。
- `/shop`コマンドでNUIを開き、`SendNUIMessage`で商品リストをJSに渡す。
- JS側は商品を一覧表示し、購入ボタン押下で`fetch`により`RegisterNUICallback`へ商品名を送る。
- server側は「商品が実在するか」「所持金が足りるか」を確認してから所持金を減算し、結果(成功/失敗)をNUIに返す。
- 購入結果に応じて画面に成功/失敗のフィードバックを表示する。

**期待する動作**
- `/shop`実行でショップ画面が開き、マウス操作ができる(SetNuiFocus)。
- 所持金が足りない商品を購入しようとすると失敗メッセージが表示され、所持金は減らない。
- 購入に成功すると所持金が正しく減り、画面にも反映される。
- 閉じるボタンでNUIが閉じ、マウス操作がゲームに戻る。

**利用する依存関係**: なし(標準NUIのみ)。

**関連レッスン**: t2-01(イベントの基礎)/ t3-01(NUIの基礎)/ t3-02(NUIコールバック)/ t3-05(サーバー側バリデーション)/ t1-09(Config.luaの設計パターン)

## ex-03: 採掘ミニゲーム+スキルシステム(難易度2〜3・🟡/🟠)

**概要**: 特定エリアで採掘コマンドを実行するとアニメーション+プログレスバーが再生され、完了後に確率で鉱石を入手する。採掘を繰り返すとスキルレベルが上がり、レア鉱石の出現率が上がる。

**ディレクトリ構造**
```
ex03-mining/
├── fxmanifest.lua
├── client.lua
└── server.lua
```

**処理仕様**
- client.luaに`/mine`コマンドを登録し、実行するとアニメーションを再生しつつ`lib.progressBar`を表示する。
- プログレスバーが正常に完了した場合のみ、server側に採掘結果をリクエストする(キャンセル時は何も起きない)。
- server.luaに重み付き抽選テーブル(common/rare等、複数種類の鉱石)を用意し、プレイヤーの採掘スキルレベルに応じてレア鉱石の重みを補正する。
- プレイヤーごとの採掘経験値をメモリ上のテーブルで管理し、抽選のたびに加算する。経験値が閾値を超えたらレベルアップとしてチャット通知する。
- 入手した鉱石はチャットメッセージで通知する(インベントリへの実際の付与は省略可)。

**期待する動作**
- `/mine`実行でアニメーションとプログレスバーが表示される。
- プログレスバーを最後まで待つと鉱石が(確率で)入手でき、通知が出る。
- 採掘を繰り返すとスキルレベルが上がり、レア鉱石が出やすくなることが体感できる。
- プログレスバーを`canCancel`でキャンセルした場合、鉱石は入手できない。

**利用する依存関係**: `ox_lib`(プログレスバー)

**関連レッスン**: t2-07(アニメーションを再生する)/ t3-08(ox_libで通知・プログレスバーを出す)/ t3-24(釣り・採掘などのミニゲームループ)/ t3-25(スキル・経験値システム)

## ex-04: 共有倉庫(スタッシュ)システム(難易度3・🟠)

**概要**: 特定の座標にox_targetでインタラクション可能な倉庫を設置し、誰でも(または特定条件下で)アイテムを預け入れ・引き出しできるようにする。中身はDBに永続化する。

**ディレクトリ構造**
```
ex04-stash/
├── fxmanifest.lua
├── client.lua
├── server.lua
└── stash.sql
```

**処理仕様**
- stash.sqlに、スタッシュの中身を保存するテーブルを定義する(スタッシュID・アイテム名・個数の組でよい、またはJSON列でまとめる設計のどちらかを選び、Tier3-17の考え方に基づいて理由を説明できるようにする)。
- client.luaでox_targetの`addBoxZone`を使い、倉庫の位置にインタラクションを追加する。
- 「開く」を選択したらserver側にリクエストを送り、現在のスタッシュの中身を取得してNUIまたはチャットで表示する。
- アイテムを預け入れる処理・引き出す処理をそれぞれ実装し、プレイヤーの所持数チェック(預け入れ時)とスタッシュの在庫チェック(引き出し時)をserver側で行う。
- 変更があるたびにDBへ保存する(Tier3-15のオートセーブの考え方を使ってもよい)。

**期待する動作**
- 倉庫に近づいてox_targetの選択肢が表示され、選ぶと中身が確認できる。
- アイテムを預けると、プレイヤーの所持数が減り、スタッシュの中身が増える。
- サーバーを再起動しても、スタッシュの中身がDBから正しく復元される。
- 存在しないアイテムを引き出そうとする、所持数を超えて預けようとする等の不正な操作が失敗する。

**利用する依存関係**: `oxmysql`, `ox_target`, (任意で`ox_inventory`)

**関連レッスン**: t3-03(DB連携の基礎)/ t3-04(アイテム・インベントリの基本)/ t3-07(ox_targetでインタラクションを作る)/ t3-17(JSON保存 vs リレーショナル設計)

## ex-05: フレームワーク連携ガレージ(難易度4・🔴)

**概要**: ESX/QBCoreいずれかのフレームワークと連携し、プレイヤーが所有する車両をガレージで出し入れできるシステムを作る。出庫時にダメージ状態も復元する。

**ディレクトリ構造**
```
ex05-garage/
├── fxmanifest.lua
├── client.lua
├── server.lua
└── garage.sql
```

**処理仕様**
- garage.sqlに所有車両テーブル(identifier, model, plate, garage, stored, fuel, engine_health, body_health等)を定義する。
- server起動時 or プレイヤーログイン完了イベント(esx:playerLoaded / QBCore:Client:OnPlayerLoadedに相当するserver版)のタイミングでフレームワークを検知する。
- ox_targetでガレージの位置にインタラクションを追加し、「出庫」を選ぶと所有車両一覧(そのガレージに格納中のもの)を取得して表示する。
- 出庫時、DBに保存されたダメージ状態・燃料を復元してから車両を生成する。
- 車両に乗った状態でox_targetから「格納」を選ぶと、現在のダメージ状態・燃料をDBに保存し、車両を削除する。
- 既に出庫中の車両をもう一度出庫できないよう、`stored`フラグを必ず確認する。

**期待する動作**
- ガレージで所有車両一覧が表示され、選択すると車両が出てくる。
- 車両にダメージを与えてから格納し、再度出庫すると同じダメージ状態で出てくる。
- 既に出ている車両を二重に出庫しようとすると拒否される。
- 導入しているフレームワーク(ESX/QBCoreのどちらか)に応じて、正しいAPIでプレイヤーデータ・識別子を取得できている。

**利用する依存関係**: `oxmysql`, `ox_target`, ESXまたはQBCore(どちらか一方)

**関連レッスン**: t4-01(ESX/QBCore/Qbox/oxの基本)/ t4-09(ログイン完了イベントを使う)/ t2-06(車両を生成・操作する)/ t2-14(車両の修理・ダメージ管理)/ t3-07(ox_targetでインタラクションを作る)/ t3-18(ガレージシステムの基礎設計)

## ex-06: okok連携ATM(難易度4・🔴)

**概要**: 街中のATMプロップにox_targetでインタラクションを追加し、okokBankingV2の口座から入出金でき、結果をokokNotifyで通知するシステムを作る。

**ディレクトリ構造**
```
ex06-atm/
├── fxmanifest.lua
├── client.lua
└── server.lua
```

**処理仕様**
- client.luaでATMのモデル(`addModel`)またはATM設置座標(`addBoxZone`)にox_targetのインタラクションを追加する。
- 「入金」「出金」の2つの選択肢を用意し、選択するとserver側にリクエストを送る(金額はコマンド引数やNUI入力等、任意の方法で受け取ってよいが、送られてきた値をそのまま信用しない設計にする)。
- server側でプレイヤーの現金所持額(フレームワークAPI経由)と、口座残高(okokBankingV2の`GetAccount`)の両方を確認してから、`AddMoney`/`RemoveMoney`で処理する。
- 処理結果を`AddTransaction`で記録し、`okokNotify`で成功/失敗を通知する。

**期待する動作**
- ATMに近づいてox_targetの選択肢が表示される。
- 入金すると所持現金が減り、口座残高が増える(逆に出金は口座残高が減り所持現金が増える)。
- 所持金/残高が足りない場合は失敗し、okokNotifyでエラー通知が出る。
- 取引が取引履歴(`GetPlayerTransactions`)から確認できる。

**利用する依存関係**: `okokNotify`, `okokBanking`, `ox_target`, ESXまたはQBCore

**関連レッスン**: t4-01(ESX/QBCore/Qbox/oxの基本)/ t4-03(okokシリーズと連携する)/ t4-06(okokBankingV2と連携する)/ t3-05(サーバー側バリデーション)/ t3-07(ox_targetでインタラクションを作る)

## ex-07: マルチresource強盗ミッション(難易度5・⚫)

**概要**: 複数resourceで構成された強盗ミッション。ドアを解除して侵入すると警察に通報が届き、成功すると報酬が支払われる。参加グループはルーティングバケットで隔離し、複数グループが同時に進行できるようにする。

**ディレクトリ構造**
```
ex07-heist-core/            -- 進行管理・報酬支払いのAPIをexportsで公開
├── fxmanifest.lua
├── client.lua
└── server.lua

ex07-heist-door/             -- ox_doorlockと連携したドア解除ギミック
├── fxmanifest.lua           -- dependency 'ex07-heist-core', dependency 'ox_doorlock'
└── client.lua

ex07-heist-dispatch/         -- cd_dispatchへの通報とDiscordログ
├── fxmanifest.lua           -- dependency 'ex07-heist-core'
└── server.lua
```

**処理仕様**
- `ex07-heist-core`が強盗の開始・進行状況・終了を管理する中心resourceとなる。開始コマンド実行時、参加プレイヤーを一意なルーティングバケットに移動させ、強盗用のNPC・ドア等の生成物も同じバケットに紐付ける。
- 進行状況(例: `doorBreached`, `safeOpened`)をStateBagsで管理し、`AddStateBagChangeHandler`で他の参加者のUIに変化を伝える。
- `ex07-heist-core`は他resourceから呼び出せるよう、`exports`で「ミッション開始」「報酬支払い」等の関数を公開する。
- `ex07-heist-door`は、ox_doorlockのドアを一定の条件(例: プログレスバーの完了)を満たしたら解錠する。解錠と同時に、コアの`exports`経由でStateBagsの`doorBreached`をtrueにする。
- `ex07-heist-dispatch`は、`doorBreached`の変化を検知したらcd_dispatchで警察に通報を送り、同時にDiscord Webhookで「強盗が開始された」ログを管理者チャンネルに送信する。
- ミッション成功時、参加プレイヤー全員にokokBanking等で報酬を分配し、ルーティングバケットを0に戻して通常ワールドに帰還させる。
- 参加プレイヤーが強盗中に切断した場合(`playerDropped`)、そのプレイヤーの生成物・状態を後始末する。

**期待する動作**
- 強盗を開始すると、参加プレイヤーだけが専用インスタンスに移動し、他の一般プレイヤーとは干渉しない(同じ座標に一般プレイヤーがいても見えない)。
- 同時に別グループが同じ強盗を開始しても、互いに干渉しない(2件同時進行できる)。
- ドアを解錠すると、警察役のプレイヤーに通報が届き、Discordにもログが残る。
- ミッション完了で報酬が支払われ、参加者は元のワールドに戻る。
- ミッション中に離脱したプレイヤーがいても、他の参加者の進行に支障が出ない。

**利用する依存関係**: `ox_doorlock`, `cd_dispatch`, `okokBanking`(報酬支払い), Discord Webhook, ESXまたはQBCore

**関連レッスン**: t3-06(exportsで関数を公開する)/ t3-09(複数resourceにまたがるプロジェクト構成のコツ)/ t4-14(ox_doorlockでドアを施錠する)/ t4-16(cd_dispatchで警察無線通知を送る)/ t5-03(StateBagsによる同期)/ t5-08(ルーティングバケットでインスタンスを分ける)/ t5-09(StateBagsの応用パターン)/ t3-22(Discord Webhookでログ収集する)/ t2-15(切断理由の取得と後処理)/ t4-06(okokBankingV2と連携する)

## ex-08: 【lb-phoneトラック】メッセージ/掲示板アプリ(難易度3・🟠)

**概要**: lb-phoneのカスタムアプリとして、プレイヤー間でメッセージを送り合える簡易メッセージ/掲示板アプリを作る。ex-02(NUI+イベント)のパターンをlb-phone文脈に適用する演習。

**ディレクトリ構造**
```
ex08-messenger/
├── fxmanifest.lua
├── client.lua
├── server.lua
├── messenger.sql
└── ui/
    ├── index.html      -- 一覧画面・詳細画面(t4-22の画面遷移パターンを使用)
    ├── style.css
    └── script.js
```

**処理仕様**
