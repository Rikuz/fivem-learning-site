ox_doorlock × Job確認: 職業によって開閉できるドアを制限する

やりたいこと

警察署の武器庫のドアのように、「特定の職業(Job)に就いているプレイヤーだけが開閉できるドア」を実装する。

組み合わせるレッスン

  • ox_doorlockでドアを施錠するTier4-14
  • フレームワークで職業(Job)システムを使うTier4-02

コード例

server.lua: Job確認後にドアを解錠する

RegisterNetEvent('recipe:requestToggleDoor')
AddEventHandler('recipe:requestToggleDoor', function(doorId, requiredJob)
    local playerId = source

    -- Tier4-01/Tier4-02のフレームワーク連携でJobを確認する(ESXの例)
    local xPlayer = ESX.GetPlayerFromId(playerId)
    if not xPlayer or xPlayer.job.name ~= requiredJob then
        TriggerClientEvent('myscript:notify', playerId, 'この職業では開閉できません', 'error')
        return
    end

    -- Job確認が通った場合のみドアを操作する(Tier4-14参照)
    local door = exports.ox_doorlock:getDoor(doorId)
    if not door then return end

    exports.ox_doorlock:setDoorState(doorId, not door.state)
end)

client.lua: インタラクションから呼び出す

exports.ox_target:addBoxZone({
    coords = vec3(450.0, -980.0, 30.0), -- 武器庫のドア座標
    size = vec3(1.5, 1.5, 2.5),
    options = {
        {
            name = 'toggle_armory_door',
            icon = 'fa-solid fa-lock',
            label = '武器庫のドアを操作する',
            onSelect = function()
                TriggerServerEvent('recipe:requestToggleDoor', 'armory_door', 'police')
            end,
        },
    }
})

注意点

  • Job確認は必ずserver側で行ってください。client側のonSelectだけで判定すると、直接イベントを発火されて回避されます(Tier3-05参照)。
  • QBCore/Qboxを使う場合はJob取得の書き方が異なります(Tier4-01参照)。xPlayer.job.nameの部分をフレームワークに合わせて書き換えてください。
