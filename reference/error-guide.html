エラーメッセージ集

開発中によく遭遇する詰まりポイントと、その典型的な原因・対処法をまとめています。Tier1-05「デバッグの基本」と合わせて活用してください。まずF8コンソール(client側)またはサーバーを起動しているターミナル(server側)でエラーメッセージのファイル名と行番号を確認するのが第一歩です。

Error parsing script @resource-name/client.lua: ...

原因: Luaの構文エラー。endの数が合っていない、カンマ・カッコの閉じ忘れ等。

対処: メッセージに含まれる行番号を確認し、その付近のブロック(function/if/for等)の対応関係を確認する。(Tier1-05)

attempt to call a nil value (global 'lib')

原因: ox_libが読み込まれる前にlib.xxxを呼んでいる。多くはox_libの初期化スクリプト読み込みやdependency指定の不足。

対処: fxmanifest.luaにdependency 'ox_lib'と、必要に応じてclient_script '@ox_lib/init.lua'を追加する。(Tier3-08)

attempt to index a nil value (global 'XXX') / attempt to call a nil value (field 'XXX')

原因: 変数名のタイプミス、未定義のテーブル/関数へのアクセス。または呼び出し先resourceのexportsがまだ起動していない。

対処: 変数名のスペルを確認する。exports呼び出しの場合は、呼び出し先resourceが自分より先に起動しているか(dependencyの指定)を確認する。(Tier3-06)

Could not find resource resource-name(サーバーコンソールでensure実行時)

原因: resource名のタイポ、または対象フォルダがresourcesディレクトリの直下(または設定したパス)に置かれていない。

対処: フォルダ名とensureに指定した名前が完全一致しているか確認する。server.cfgのset resources_path設定もあわせて確認する。

SCRIPT ERROR: ... execution of native XXXXXXXX failed: ...

原因: native関数に渡している引数の型・個数が正しくない(数値を期待する箇所に文字列を渡した、座標をvec3ではなくx,y,z個別で渡すべき所を間違えた等)。

対処: エラーに含まれるnative名でTier1-10のnative参照方法を使い、公式リファレンスの引数の型を確認する。

NUIのfetch()がいつまでも完了しない(ボタンを押しても反応がない)

原因: Lua側のRegisterNUICallbackハンドラ内でcb(...)を呼び忘れている。

対処: コールバック関数の最後に必ずcb('ok')等を呼ぶ。(Tier3-02)

NUIのui/index.htmlをブラウザで直接開くと GetParentResourceName is not defined 等のエラーになる

原因: GetParentResourceName()やNUI宛のfetch()は、FiveMのゲームクライアント内(NUI環境)でのみ動作する。これはバグではなく仕様。

対処: 見た目(レイアウト・CSS)の確認はブラウザ単体でもできるが、実際の通信確認はFiveM実機で行う。(Tier3-02)

attempt to index a nil value (global 'MySQL')

原因: oxmysqlが起動していない、または自分のresourceより後に起動している。

対処: fxmanifest.luaにdependency 'oxmysql'を追加し、サーバーコンソールでoxmysqlが正常に起動しているか確認する。(Tier3-03)

resourceをrestartするたびにNPC/Blip/オブジェクトが増えていく

原因: onResourceStopでの後片付け(生成物の削除)を実装していない。

対処: resource停止時にDeletePed/DeleteEntity/RemoveBlipで確実に削除する処理を追加する。(Tier2-02)

生成したPed/車両/オブジェクトが透明、または一部パーツが欠けて表示される

原因: RequestModel直後、モデルの読み込み完了(HasModelLoaded)を待たずに生成処理を行っている。

対処: while not HasModelLoaded(model) do Wait(0) endで読み込み完了を待ってから生成する。(Tier2-02)

アニメーションが再生されない、または途中で止まる

原因: RequestAnimDict直後、HasAnimDictLoadedで読み込み完了を待っていない。

対処: アニメ辞書の読み込み待ちループを必ず挟む。(Tier2-07)

IsPlayerAceAllowedが常にfalseを返す

原因: server.cfgのadd_ace/add_principalの記述順や、識別子の形式(identifier.steam:...等)のミス。

対処: add_principalでプレイヤーをグループに所属させてから、add_aceでそのグループに権限を付与する順序になっているか確認する。(Tier2-04)

StateBagsの変更が他プレイヤーの画面に反映されない

原因: :set(key, value, replicated)の第3引数(replicated)をtrueにしていない。

対処: 他clientにも同期したい値は必ず第3引数をtrueにする。(Tier5-03)

TriggerServerEvent/TriggerClientEventを呼んだのにイベントが実行されない

原因: 受け取り側でRegisterNetEventの登録漏れ、またはイベント名のタイポ、client/serverの実行側を取り違えている。

対処: 発火側と受信側でイベント名が完全一致しているか、受信側のファイルが正しくclient_script/server_scriptとして登録されているか確認する。(Tier2-01)

attempt to compare number with nil / attempt to perform arithmetic on a nil value

原因: tonumber()の変換に失敗した値(存在しない引数、想定外の文字列等)をそのまま計算・比較に使っている。

対処: tonumber()の戻り値がnilでないかを必ずチェックしてから使う(Tier3-05のバリデーションと同じ考え方)。

ox_targetの選択肢がインタラクションしても表示されない

原因: addBoxZoneの座標がずれている、addModelのモデル名が実際のプロップと一致していない、またはox_target自体が起動していない。

対処: 座標・モデル名を再確認し、ensure ox_targetが正しく実行されているか確認する。(Tier3-07)

「1人で動作確認したときは問題なかったのに、本番導入後に不具合が起きた」

原因: restart耐性・複数人同時利用・不正な入力への耐性を、公開前に確認していなかった典型パターン。

対処: Tier3-46のチェックリスト(restart確認・複数クライアント確認・不正入力確認)を公開前に一通り実施する。(Tier3-46)

該当するエラーが見つかりませんでした。
