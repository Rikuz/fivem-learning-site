アイテム・インベントリの基本

結論

このレッスンを終えると、プレイヤーごとのアイテム所持数をテーブルで管理し、増減させるという、インベントリシステムの土台となる考え方が理解できるようになります。

説明

実際のRPサーバーでは、既存のインベントリフレームワーク(ox_inventory, qb-inventoryなど)を使うことが多いですが、その内部で行われている「テーブルでアイテムと個数を管理し、DBに保存する」という基本の考え方は共通しています。ここではシンプルな自作の仕組みを作りながら理解します。

コード例

server.lua: プレイヤーごとのインベントリをメモリ上で管理する

-- playerId(数値) -> { [アイテム名] = 個数 } の対応表
local inventories = {}

local function getInventory(playerId)
    if not inventories[playerId] then
        inventories[playerId] = {}
    end
    return inventories[playerId]
end

local function addItem(playerId, itemName, amount)
    local inventory = getInventory(playerId)
    inventory[itemName] = (inventory[itemName] or 0) + amount
end

local function removeItem(playerId, itemName, amount)
    local inventory = getInventory(playerId)
    local current = inventory[itemName] or 0

    if current < amount then
        return false -- 所持数が足りない
    end

    inventory[itemName] = current - amount
    return true
end

server.lua: DBへの保存(oxmysql, Tier3-03参照)

local function saveInventory(identifier, playerId)
    local inventory = getInventory(playerId)
    local json = json.encode(inventory) -- FiveMのLuaにはjson.encode/decodeが標準搭載されている

    MySQL.Async.execute('UPDATE users SET inventory = @inventory WHERE identifier = @identifier', {
        ['@inventory'] = json,
        ['@identifier'] = identifier
    })
end

local function loadInventory(identifier, playerId)
    MySQL.Async.fetchAll('SELECT inventory FROM users WHERE identifier = @identifier', {
        ['@identifier'] = identifier
    }, function(result)
        if result and result[1] and result[1].inventory then
            inventories[playerId] = json.decode(result[1].inventory)
        end
    end)
end

使用例

RegisterNetEvent('myscript:givePotion')
AddEventHandler('myscript:givePotion', function()
    local playerId = source
    addItem(playerId, 'potion', 1)
    TriggerClientEvent('myscript:notify', playerId, 'ポーションを1個入手しました')
end)

ox_inventoryを使う場合(実際のexport構文)

実運用では、上記のような自作インベントリではなくox_inventory(FiveMで広く使われているインベントリリソース)を導入することが多いです。その場合はexport経由でアイテムを操作します。

-- アイテムを追加する(成功時true)
local success = exports.ox_inventory:AddItem(source, 'water', 1)

-- アイテムを減らす(成功時true。所持数が足りない場合はfalse)
local removed = exports.ox_inventory:RemoveItem(source, 'water', 1)

-- 所持数を確認する
local count = exports.ox_inventory:GetItemCount(source, 'water')

if count >= 1 then
    exports.ox_inventory:RemoveItem(source, 'water', 1)
    TriggerClientEvent('myscript:notify', source, '水を1本消費しました')
end

※sourceはプレイヤーID(数値)。第4引数にmetadata(耐久値・刻印などアイテムごとの付加データ)、第5引数にslot番号を指定できる場合があります。ox_inventoryはバージョンによって引数が増減することがあるため、導入しているox_inventoryのREADME・公式ドキュメントも必ず確認してください。

注意点・よくあるミス

  • アイテムの増減は必ずserver側の関数(addItem/removeItem)を通してください。clientから直接インベントリのテーブルを書き換える構造にすると、改ざんの余地が生まれます。
  • removeItemで所持数チェックをせずに引き算だけすると、マイナスの個数になってしまう(=存在しないはずのアイテムを消費できてしまう)バグにつながります。上記コード例のように必ず所持数を確認してから減算してください。
  • プレイヤーが切断したときにinventories[playerId]を消し忘れると、メモリ上にデータが残り続けます(メモリリーク)。AddEventHandler('playerDropped', ...)で保存とクリーンアップを行いましょう。

補足

実運用では、この自作の仕組みをそのまま使うより、コミュニティで広く使われているインベントリフレームワーク(ox_inventoryなど)を導入し、そのエクスポート関数を呼ぶ形にすることが多いです。ただし、内部でどんな処理が行われているかを理解しておくと、トラブルシューティングや独自機能の追加がしやすくなります。
