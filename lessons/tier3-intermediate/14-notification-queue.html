通知のキュー管理

結論

このレッスンを終えると、複数の通知がほぼ同時に送られてきても、画面上に重ならず順番に表示するキュー(待ち行列)の仕組みをJS側に実装できるようになります。

こんな時に使う: 自作の通知UI(Tier3-01のNUI応用)で、短時間に何度も通知が来ると表示が重なってしまう問題を解決したいとき。

説明

okokNotify(Tier4-03)のような既製の通知スクリプトは、内部でこの「キュー」の仕組みを持っています。キュー(先に入れたものから順に取り出される待ち行列のデータ構造)に通知を積んでおき、1つ表示が終わったら次を取り出して表示する、という制御を行います。

コード例

ui/script.js: 通知キューを実装する

const notificationQueue = [];
let isShowingNotification = false;

function enqueueNotification(notification) {
  notificationQueue.push(notification);
  processQueue();
}

function processQueue() {
  if (isShowingNotification || notificationQueue.length === 0) {
    return; // 既に表示中、またはキューが空なら何もしない
  }

  isShowingNotification = true;
  const notification = notificationQueue.shift(); // 先頭(最も古い通知)を取り出す

  showNotificationElement(notification);

  setTimeout(() => {
    hideNotificationElement();
    isShowingNotification = false;
    processQueue(); // 次の通知があれば続けて処理する
  }, notification.duration || 3000);
}

window.addEventListener('message', (event) => {
  if (event.data.action === 'notify') {
    enqueueNotification(event.data);
  }
});

Lua側からの送信は変更不要

SendNUIMessage({
    action = 'notify',
    title = '入手',
    description = 'アイテムを入手しました',
    duration = 3000
})

-- 短時間に連続で送っても、JS側のキューが順番に処理してくれる
SendNUIMessage({ action = 'notify', title = '通知1' })
SendNUIMessage({ action = 'notify', title = '通知2' })

注意点・よくあるミス

  • isShowingNotificationのようなフラグの更新を忘れる(setTimeoutのコールバック内でfalseに戻し忘れる等)と、以降の通知が永久に表示されなくなるバグになります。
  • 通知が大量に送られ続けるケース(連打対策の抜け穴など)を想定し、キューの最大件数を制限する(古いものを間引く)ことも実運用では検討してください。
  • 複数の通知を「重ねて複数個同時に表示する」UI(多くの通知系スクリプトが採用しているスタイル)にしたい場合は、この「1つずつ順番に」ではなく、表示中リストに追加して一定時間ごとに消す設計の方が適しています。用途に応じて選んでください。

補足

キュー(先入れ先出し、FIFO)は通知以外にも、Tier5-02の非同期DB処理や、連続するアニメーション再生の管理など、様々な場面で使える汎用的な考え方です。
