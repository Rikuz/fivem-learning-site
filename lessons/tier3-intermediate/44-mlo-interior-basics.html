MLO/インテリア導入の基礎

結論

このレッスンを終えると、既製のMLO(カスタムインテリア。YTYP/YMAPとしてパッケージされた建物内装)をリソースとして導入し、家具の表示/非表示をinterior entity setで切り替えることができるようになります。Tier4-34〜36の住居システムに、既製のリッチな内装を組み込む際の土台になります。

こんな時に使う: ゼロから内装をスクリプトで組み立てるのではなく、既製の(自作または配布・購入した)MLOアセットをサーバーに導入したいとき。

説明

MLO(Map Loaded Object)は、GTA V標準の内装を上書き/追加する形で配置される、専用に作られた建物内装データです。実体はYTYP(型定義)・YMAP(配置情報)等のファイル群で、通常stream/フォルダにまとめられます。導入自体はスクリプトを書く作業ではなく、fxmanifest.luaに「これはマップリソースである」と正しく宣言する作業が中心です。

コード例

fxmanifest.lua: MLOリソースとして正しく認識させる

fx_version 'cerulean'
game 'gta5'

author '自分の名前'
description 'カスタムMLOインテリア'
version '1.0.0'

-- このリソースがマップ(YMAP/YTYP等)であることをFiveMに伝える
this_is_a_map 'yes'

files {
    'stream/**/*.ymap',
    'stream/**/*.ytyp',
    'stream/**/*.ydr',
    'stream/**/*.ytd',
}

-- YTYP(内装の型定義)を確実に読み込ませる。これを忘れるとYMAPは配置されても
-- 内装の実体(部屋・家具)が認識されず、空っぽの内装になってしまう
data_file 'DLC_ITYP_REQUEST' 'stream/my_mlo.ytyp'

client.lua: interior entity setで家具の表示/非表示を切り替える

local function toggleFurnitureSet(coords, entitySetName, enable)
    local interiorId = GetInteriorAtCoords(coords.x, coords.y, coords.z)
    if interiorId == 0 then return end

    if enable then
        ActivateInteriorEntitySet(interiorId, entitySetName)
    else
        DeactivateInteriorEntitySet(interiorId, entitySetName)
    end

    -- entity setの変更を実際の見た目に反映させるために必須
    RefreshInterior(interiorId)
end

-- 使用例: 家具プリセット「luxury」を表示する
RegisterCommand('togglefurniture', function()
    local coords = GetEntityCoords(PlayerPedId())
    toggleFurnitureSet(coords, 'luxury', true)
end, false)

注意点・よくあるミス

  • this_is_a_map 'yes'とdata_file 'DLC_ITYP_REQUEST' ...の2つを両方書き忘れると、「YMAPは読み込まれているのに内装が空っぽ/一部の家具が出ない」という典型的な不具合になります。MLOが正しく表示されないときは、まずこの2点を確認してください。
  • entitySetName(家具プリセットの名前)は、MLO作成者がYTYPで定義した名称と完全に一致している必要があります。名前はMLO配布元のドキュメントやYTYPファイルの中身を確認してください。
  • 複数のMLOリソースが同じ座標に干渉する(既存の内装と衝突する)ことがあります。導入前に配置座標が既存のリソースと重複していないか確認しましょう。
  • MLOはファイルサイズが大きくなりがちです。導入しすぎるとクライアントの読み込み時間やストリーミング負荷が増えるため、Tier5-01のパフォーマンス計測と合わせて確認することをおすすめします。

補足

MLOアセット自体の作成(CodeWalker等の外部ツールでのモデリング・YTYP編集)は本サイトのスコープ外(Luaスクリプト開発に特化しているため)です。ここで扱っているのは「既に作られたMLOをリソースとして正しく読み込ませる」部分に限定しています。this_is_a_map・data_file・ActivateInteriorEntitySet等の構文はCfx公式ドキュメント(docs.fivem.net)で確認済みですが、配布元によってentity set名やフォルダ構成が異なるため、導入時は必ず配布元のREADMEも確認してください。次のレッスン(Tier3-45)では、内装ではなく屋外のカスタムプロップ配置を扱います。
