🟡 中級 🖥️ UI表示(NUI)

常駐HUDの基礎設計(NUIを常時表示するパターン)

結論

このレッスンを終えると、「開く/閉じる」タイプのNUI(Tier3-01)とは異なり、ゲームプレイ中ずっと画面に表示され続けるHUDをNUIで作ることができるようになります。スピードメーターやステータスバーなど、あらゆる自作HUDの土台です。

こんな時に使う: デフォルトのGTA V HUDではなく、サーバー独自のHUDを画面に常時表示したいとき。

説明

Tier3-01で学んだNUIは「SetNuiFocus(true, true)でマウス操作を奪い、閉じたらfalse, falseに戻す」という一時的な表示でした。HUDはこれと違い、マウス・キーボード操作を奪わず、ゲームプレイ中ずっと表示され続ける必要があります。そのためSetNuiFocusは一切呼ばず、CSS側で「クリックを無視する」設定をしておくことがポイントです。

コード例

fxmanifest.lua: HUD用のui_pageを登録する

fx_version 'cerulean'
game 'gta5'

ui_page 'ui/index.html'

files {
    'ui/index.html',
    'ui/style.css',
    'ui/script.js'
}

client_script 'client.lua'

ui/style.css: HUD全体をクリック透過にする

html, body {
  background: transparent;
  margin: 0;
  /* HUD自体はゲームの操作を邪魔してはいけないので、クリックを常に透過させる */
  pointer-events: none;
}

#hud {
  position: fixed;
  bottom: 20px;
  left: 20px;
  font-family: sans-serif;
  color: white;
  text-shadow: 0 0 4px rgba(0, 0, 0, 0.8);
}

client.lua: SetNuiFocusを一切呼ばず、resource起動時から表示され続ける

-- HUDは「開く/閉じる」操作がなく、resourceが起動している間はずっと表示されたままにする
-- (SetNuiFocusを呼んでいないため、プレイヤーの操作は一切妨げない)

CreateThread(function()
    while true do
        Wait(500) -- 更新間隔。Wait(0)は無駄に負荷をかけるので避ける(Tier5-01参照)

        local ped = PlayerPedId()
        SendNUIMessage({
            action = 'updateHud',
            health = GetEntityHealth(ped),
        })
    end
end)

注意点・よくあるミス

  • HUD用のNUIにSetNuiFocus(true, true)を呼んでしまうと、常時マウス操作を奪ってしまい、ゲームがプレイできなくなります。HUDは基本的にSetNuiFocusを呼ばない設計にしてください。
  • CSSでpointer-events: noneを忘れると、HUDの要素がゲーム画面のクリックを吸収してしまうことがあります。HUD全体に必ず設定しておきましょう。
  • 更新頻度をWait(0)(毎フレーム)にすると、不要なSendNUIMessage呼び出しが大量に発生しパフォーマンスを悪化させます(Tier5-01参照)。体力等の頻繁に変わらない値は数百ms間隔で十分です。

補足

次のレッスン(Tier3-40)では、この常駐HUDにスピードメーターとミニマップのカスタマイズを追加します。値が変化した時だけSendNUIMessageを送る(前回値との比較)という工夫も、パフォーマンスを保つ上で有効です。
