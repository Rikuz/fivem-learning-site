ox_targetでインタラクションを作る

結論

このレッスンを終えると、ox_target(FiveMで広く使われるターゲティング・「third-eye」ライブラリ)でNPCやエリアに近づいたときのインタラクション選択肢を表示することができるようになります。

説明

Tier2-03で学んだBlip/Markerは「目印を見せる」ためのものでしたが、「近づいて対象を見ると選択肢が出て、選ぶと処理が実行される」というインタラクションは、Tier2-04のキー入力判定を自作するよりもox_targetのようなターゲティングライブラリを使う方が簡単で、見た目も統一されます。

ox_targetには、決まった範囲(ゾーン)を対象にするaddBoxZoneと、特定のモデル(ped/vehicle等)を対象にするaddModelなど複数の登録方法があります。

コード例

ボックス型のゾーンにインタラクションを追加する

exports.ox_target:addBoxZone({
    coords = vec3(442.5363, -1017.666, 28.85637),
    size = vec3(3, 3, 3),
    rotation = 45,
    debug = false,
    options = {
        {
            name = 'open_shop_menu',
            event = 'myscript:openShopMenu', -- 選択時にTriggerEventで発火するイベント名
            icon = 'fa-solid fa-cart-shopping',
            label = 'ショップを開く',
        }
    }
})

選択されたイベントを受け取る

RegisterNetEvent('myscript:openShopMenu')
AddEventHandler('myscript:openShopMenu', function()
    print('ショップメニューを開く処理をここに書く')
end)

特定モデルのNPC全てにインタラクションを追加する

exports.ox_target:addModel('a_m_m_business_01', {
    {
        name = 'talk_to_npc',
        icon = 'fa-solid fa-comment',
        label = '話しかける',
        onSelect = function(data)
            -- data.entity: 対象になったエンティティのハンドル
            print('選択されたNPC: ' .. tostring(data.entity))
        end,
    }
})

注意点・よくあるミス

  • options内の各項目はevent(TriggerEventで発火するイベント名)またはonSelect(直接呼ばれる関数)のどちらか一方を指定します。両方書いても両方は実行されない・意図しない挙動になるため、どちらか一方に統一してください。
  • addModelはモデル単位で登録するため、そのモデルのエンティティ全てにインタラクションが付きます。特定の1体だけに付けたい場合はaddLocalEntity(エンティティハンドル指定)やaddEntity(ネットワークID指定)を使ってください。
  • ox_targetはox_lib(次のレッスンで扱います)に依存していることが多く、導入時はox_lib・ox_targetの両方をensureし、自分のresourceのfxmanifest.luaにもdependency 'ox_target'を指定しておくと起動順序のトラブルを防げます。

補足

本レッスンのexport構文(addBoxZone、addModelの基本形)はOverextended公式ドキュメント(overextended.dev/docs/ox_target)で確認済みですが、ox_targetは活発に開発が続いているリソースで、オプションが追加される場合があります。addEntity・addLocalEntity・removeZoneなど他の関数も含め、導入しているバージョンの公式ドキュメントを確認してください。
