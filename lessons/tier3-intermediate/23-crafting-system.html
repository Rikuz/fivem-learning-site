クラフト(製作)システムの基礎

結論

このレッスンを終えると、「必要な素材が揃っているか確認→素材を消費→完成品を付与する」という、クラフトシステムの基本的な処理フローを実装できるようになります。

こんな時に使う: 料理・薬品・武器改造など、複数の素材から新しいアイテムを作れるようにしたいとき。

説明

クラフトの本質は、Tier3-04で学んだインベントリ操作(addItem/removeItem)を「レシピ」に沿って組み合わせることです。レシピをConfig.lua(Tier1-09)にデータとして定義しておくと、新しい製作物を追加するのも簡単になります。

コード例

Config.lua: レシピの定義

Config.Recipes = {
    {
        result = { name = 'bandage', amount = 1 },
        ingredients = {
            { name = 'cloth', amount = 2 },
            { name = 'alcohol', amount = 1 },
        },
        craftTimeMs = 5000,
    },
}

server.lua: レシピに沿って製作する

local function findRecipe(itemName)
    for _, recipe in ipairs(Config.Recipes) do
        if recipe.result.name == itemName then
            return recipe
        end
    end
    return nil
end

local function hasEnoughIngredients(playerId, recipe)
    for _, ingredient in ipairs(recipe.ingredients) do
        local count = exports.ox_inventory:GetItemCount(playerId, ingredient.name)
        if count < ingredient.amount then
            return false
        end
    end
    return true
end

RegisterNetEvent('crafting:craftItem')
AddEventHandler('crafting:craftItem', function(itemName)
    local playerId = source
    local recipe = findRecipe(itemName)

    if not recipe then return end
    if not hasEnoughIngredients(playerId, recipe) then
        TriggerClientEvent('myscript:notify', playerId, '素材が足りません')
        return
    end

    -- 素材を全て消費してから、完成品を渡す
    for _, ingredient in ipairs(recipe.ingredients) do
        exports.ox_inventory:RemoveItem(playerId, ingredient.name, ingredient.amount)
    end
    exports.ox_inventory:AddItem(playerId, recipe.result.name, recipe.result.amount)

    TriggerClientEvent('myscript:notify', playerId, ('%sを製作しました'):format(recipe.result.name))
end)

client.lua: 製作時間を演出する(ox_lib、Tier3-08参照)

RegisterCommand('craft', function(args)
    local itemName = args[1]

    if lib.progressBar({ duration = 5000, label = '製作しています...', canCancel = true }) then
        TriggerServerEvent('crafting:craftItem', itemName)
    end
end, false)

注意点・よくあるミス

  • 素材の消費と完成品の付与を分けて考えず、必ず「消費に成功してから」完成品を渡す順序にしてください。先に完成品を渡してしまうと、素材が足りない場合の取り消し処理が複雑になります。
  • 製作時間の演出(プログレスバー)はclient側の見た目にすぎません。実際の判定(素材があるか、製作が完了したか)は必ずserver側で行い、client側のプログレスバーが完了したという通知だけを信用しないでください(client側から不正に「完了した」というイベントを送られる可能性があるため)。
  • レシピが増えるほどfindRecipeの線形探索(先頭から順に調べる方法)が遅くなります。レシピ数が多い場合は、アイテム名をキーにしたテーブル(連想配列)に変換しておくと高速化できます。

補足

Tier3-24「釣り・採掘などのミニゲームループ」と組み合わせて「採取した素材でクラフトする」という一連の生産チェーンを作ることもよくあります。
