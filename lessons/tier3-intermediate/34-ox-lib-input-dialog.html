ox_libで入力ダイアログを出す(lib.inputDialog)

結論

このレッスンを終えると、プレイヤーに文字や数値を入力してもらうフォームを、NUIを自作せずに数行で表示することができるようになります。「車両のナンバープレートを決める」「通報理由を入力してもらう」といった場面で、Tier3-01のNUIを1から作らずに済みます。

説明

lib.inputDialog(見出し, 行の配列)を呼ぶと、指定した入力欄を持つフォームが表示されます。プレイヤーが入力して確定すると、各欄の値が配列として返ってきます。非同期関数なので、結果を受け取るにはawait可能な文脈(コルーチン、Tier5-07参照)で呼び出す必要があります。

コード例

シンプルなテキスト入力

RegisterCommand('setplatename', function()
    local input = lib.inputDialog('ナンバープレートの変更', { '新しいプレート番号(8文字以内)' })
    if not input then return end -- キャンセルされた場合はnilが返る

    local newPlate = input[1]
    print('新しいプレート: ' .. newPlate)
end, false)

複数の種類の入力欄を組み合わせる

RegisterCommand('reportplayer', function()
    local input = lib.inputDialog('プレイヤーを通報', {
        { type = 'input', label = '対象プレイヤーID', required = true },
        { type = 'select', label = '理由', options = {
            { value = 'cheating', label = 'チート行為' },
            { value = 'harassment', label = '嫌がらせ' },
            { value = 'other', label = 'その他' },
        }},
        { type = 'textarea', label = '詳細' },
    })
    if not input then return end

    local targetId, reason, details = input[1], input[2], input[3]
    TriggerServerEvent('report:submit', targetId, reason, details) -- Tier3-21参照
end, false)

注意点・よくあるミス

  • 戻り値は入力欄の順番に対応した配列です。1つ目の入力欄の値はinput[1]、2つ目はinput[2]のように取得します。プロパティ名でアクセスしようとすると失敗します。
  • キャンセルされた場合はnilが返ります。if not input then return endのチェックを必ず入れてください。
  • 各行のtypeには'input'(テキスト)、'number'、'checkbox'、'select'、'slider'、'color'、'multi-select'、'date'、'date-range'、'time'、'textarea'が指定できます。用途に合わないtypeを指定すると期待したUIになりません。
  • 入力されたテキストは、送信前と同様にTier3-05のサーバー側バリデーションの対象です。フォームで受け付けたからといって安全とは限らないため、server側でも文字数チェック等を行ってください。

補足

本レッスンの構文は公式ドキュメント(overextended.dev/docs/ox_lib/Interface/Client/input)で確認済みです。第3引数にoptionsテーブルを渡すと、ダイアログの見た目や挙動をさらに細かく調整できます。バージョンによって指定できるtypeが増減する場合があるため、公式ドキュメントも確認してください。
