exportsで関数を公開する

結論

このレッスンを終えると、自分のresourceの関数を他のresourceから直接呼び出せるように公開することができるようになります。これまでのレッスンで使ってきたexports['okokNotify']:Alert(...)のような呼び出しを、今度は自分で作る側になります。

説明

これまでのTriggerEvent系(イベント)は「送りっぱなし」の通信でしたが、exportsは「関数を呼んで、戻り値をその場で受け取れる」という点が異なります。値を計算して即座に結果が欲しい場合はexports、非同期に結果を待つ・複数の相手に通知したい場合はイベント、という使い分けが基本です。

コード例

公開する側(resource名: my-utils)

-- server.lua
local function GetPlayerLevel(source)
    -- 本来はDBやフレームワークから取得する処理(ここでは簡略化のため固定値)
    return 5
end

exports('GetPlayerLevel', GetPlayerLevel)

呼び出す側(別のresource)

-- server.lua
RegisterNetEvent('myscript:checkLevel')
AddEventHandler('myscript:checkLevel', function()
    local playerId = source
    local level = exports['my-utils']:GetPlayerLevel(playerId)
    print(('プレイヤー%sのレベルは%sです'):format(playerId, level))
end)

client側でも同じ考え方で使える

-- 公開する側(client.lua)
local function IsNearShop()
    local coords = GetEntityCoords(PlayerPedId())
    return #(coords - vector3(100.0, 200.0, 30.0)) < 5.0
end

exports('IsNearShop', IsNearShop)

-- 呼び出す側(別resourceのclient.lua)
if exports['my-utils']:IsNearShop() then
    print('ショップの近くにいます')
end

注意点・よくあるミス

  • exports(...)で公開していない関数は、他のresourceから呼び出せません。「グローバル関数として定義すれば他からも見える」わけではない点に注意してください(Luaのスコープはresourceごとに独立しています)。
  • 公開する側のresourceが呼び出す側より先に起動している必要があります。fxmanifest.luaにdependency 'my-utils'を指定して起動順序を保証しましょう(Tier1-04参照)。
  • server側のexportとclient側のexportは別物です。server.luaで公開した関数はclient側からは呼べません(逆も同様)。

補足

okokNotify・okokTextUI・lb-phone・ox_inventoryなど、これまでのレッスンで登場した外部スクリプト連携は、すべてこのexportsの仕組みを使っています。自分でresourceをまたぐ共通処理(ユーティリティ関数など)を整理したい場合にも活用できます。
