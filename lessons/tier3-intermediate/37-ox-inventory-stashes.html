ox_inventory組み込みのスタッシュ登録

結論

このレッスンを終えると、ox_inventoryのRegisterStashで、DBへの永続化まで含めた倉庫(スタッシュ)をわずか数行で作ることができるようになります。演習ex-04で自作したスタッシュ(独自のDBテーブル設計から実装)と同じ機能を、ox_inventory側の仕組みだけで実現します。

説明

ex-04では、スタッシュのDB設計・預け入れ/引き出しのバリデーションを全て自分で実装しました。ox_inventoryを導入している場合、RegisterStashでスタッシュを登録しておくだけで、中身の永続化・預け入れ/引き出しのUIまでox_inventory側が処理してくれます。

コード例

server.lua: スタッシュを登録する

-- RegisterStash(id, label, slots, weight, owner)
exports.ox_inventory:RegisterStash('shared_warehouse', '共有倉庫', 50, 100000)
-- ownerを省略すると、誰でもアクセスできる共有スタッシュになる(ex-04と同じ挙動)

exports.ox_inventory:RegisterStash('locker_' .. identifier, '個人ロッカー', 20, 30000, identifier)
-- ownerにcitizenid等を指定すると、そのプレイヤー専用のスタッシュになる

resource起動時にまとめて登録する

CreateThread(function()
    exports.ox_inventory:RegisterStash('shared_warehouse', '共有倉庫', 50, 100000)
    exports.ox_inventory:RegisterStash('police_evidence', '警察の証拠品保管庫', 100, 500000, false, { police = 0 })
end)

client.lua: 登録したスタッシュを開く(ox_targetと組み合わせる例)

exports.ox_target:addBoxZone({
    coords = vec3(100.0, 200.0, 30.0),
    size = vec3(2.0, 2.0, 2.0),
    options = {
        {
            name = 'open_warehouse',
            icon = 'fa-solid fa-warehouse',
            label = '倉庫を開く',
            onSelect = function()
                exports.ox_inventory:openInventory('stash', { id = 'shared_warehouse' })
            end,
        }
    }
})

注意点・よくあるミス

  • RegisterStashはプレイヤーがそのスタッシュを開こうとする前に、必ず1度実行されている必要があります。resource起動時のスレッドでまとめて登録しておくのが確実です。
  • idはDB上でスタッシュを識別する一意な文字列です。同じidを別の場所で使い回すと、中身が共有されてしまいます(個人ロッカーを作る際にidentifierを含めるのはこのためです)。
  • ownerを指定し忘れると、誰でもアクセスできる共有スタッシュになります。個人専用にしたい場合は必ずownerを指定してください。

補足

本レッスンの構文は公式ドキュメント(overextended.dev/docs/ox_inventory/Guides/stashes)で確認済みです。groups引数(上記のpolice例)でJobごとのアクセス制限も可能です。演習ex-04で自作した設計と比較すると、「中身の永続化・UIをox_inventoryに任せ、自分は登録とアクセス制御だけ書く」という役割分担の違いが実感できるはずです。
