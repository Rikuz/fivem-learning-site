運転免許・DMV系システム

結論

このレッスンを終えると、チェックポイントを順番に通過する実技試験を作り、時間内に合格したプレイヤーにDBへ保存される運転免許を発行することができるようになります。単一の外部スクリプトが広く標準化されている分野ではないため、Tier2-18のエリア判定とTier3-03のDB連携を組み合わせた自作システムとして構築します。

こんな時に使う: 「免許を持っていないと車を借りられない/公道を走れない」という縛りをRPサーバーに導入したいとき。

説明

教習・試験は「①決められた順番でチェックポイントを通過する」「②制限時間内に完走する」「③完走できたら合格として免許をDBに記録する」という3ステップで作ります。チェックポイントの通過判定はTier2-18で学んだ距離ベースのエリア判定を使い、順番を飛ばして通過できないよう、必ず「次に通過すべきチェックポイントの番号」をserver側で管理します。

コード例

SQL: 免許テーブル

CREATE TABLE IF NOT EXISTS `driver_licenses` (
  `identifier` VARCHAR(64) PRIMARY KEY,
  `issued_at` DATETIME DEFAULT CURRENT_TIMESTAMP
);

client.lua: チェックポイントを順番に表示し、通過を検知する

local CHECKPOINTS = {
    vec3(100.0, 200.0, 30.0),
    vec3(150.0, 250.0, 30.0),
    vec3(200.0, 220.0, 30.0),
    vec3(120.0, 180.0, 30.0), -- ゴール(スタート地点付近に戻ってくる周回コース)
}
local TIME_LIMIT_MS = 3 * 60 * 1000 -- 3分以内に完走
local REACH_DISTANCE = 5.0

local testActive = false
local currentCheckpointIndex = 1
local testBlip = nil
local testEndsAt = nil

local function showCheckpointBlip(index)
    if testBlip then RemoveBlip(testBlip) end

    local coords = CHECKPOINTS[index]
    testBlip = AddBlipForCoord(coords.x, coords.y, coords.z)
    SetBlipSprite(testBlip, 1)
    SetBlipColour(testBlip, 5)
    SetBlipRoute(testBlip, true)
end

RegisterCommand('dmv_start', function()
    if testActive then return end
    testActive = true
    currentCheckpointIndex = 1
    testEndsAt = GetGameTimer() + TIME_LIMIT_MS

    showCheckpointBlip(currentCheckpointIndex)
    TriggerEvent('chat:addMessage', { args = { '[DMV]', ('試験を開始しました(制限時間%d分)'):format(TIME_LIMIT_MS / 60000) } })
end, false)

CreateThread(function()
    while true do
        Wait(500)

        if testActive then
            if GetGameTimer() >= testEndsAt then
                testActive = false
                if testBlip then RemoveBlip(testBlip) end
                TriggerEvent('chat:addMessage', { args = { '[DMV]', '時間切れで不合格です' } })
            else
                local ped = PlayerPedId()
                -- 乗車中でなければ試験にならないため、車両搭乗中かも確認する
                local vehicle = GetVehiclePedIsIn(ped, false)
                local playerCoords = (vehicle ~= 0) and GetEntityCoords(vehicle) or GetEntityCoords(ped)
                local target = CHECKPOINTS[currentCheckpointIndex]
                local distance = #(playerCoords - target)

                if distance <= REACH_DISTANCE then
                    currentCheckpointIndex = currentCheckpointIndex + 1

                    if currentCheckpointIndex > #CHECKPOINTS then
                        testActive = false
                        if testBlip then RemoveBlip(testBlip) end
                        TriggerServerEvent('dmv:requestIssueLicense')
                    else
                        showCheckpointBlip(currentCheckpointIndex)
                    end
                end
            end
        end
    end
end)

RegisterNetEvent('dmv:notify')
AddEventHandler('dmv:notify', function(message)
    TriggerEvent('chat:addMessage', { args = { '[DMV]', message } })
end)

server.lua: 免許を発行し、後で確認できるようにする

local function getIdentifier(playerId)
    return GetPlayerIdentifierByType(playerId, 'license')
end

local function hasLicense(playerId)
    local identifier = getIdentifier(playerId)
    local row = MySQL.scalar.await('SELECT identifier FROM driver_licenses WHERE identifier = ?', { identifier })
    return row ~= nil
end

RegisterNetEvent('dmv:requestIssueLicense')
AddEventHandler('dmv:requestIssueLicense', function()
    local playerId = source
    local identifier = getIdentifier(playerId)

    -- 既に持っている場合は再発行しない(INSERT IGNOREで一意制約に任せる)
    MySQL.query('INSERT IGNORE INTO driver_licenses (identifier) VALUES (?)', { identifier })

    TriggerClientEvent('dmv:notify', playerId, '合格しました!運転免許が発行されました')
end)

-- レンタカー等、免許が必要な操作の前に確認する使用例
RegisterNetEvent('rentalcar:requestRent')
AddEventHandler('rentalcar:requestRent', function()
    local playerId = source

    if not hasLicense(playerId) then
        TriggerClientEvent('dmv:notify', playerId, '運転免許を取得してください')
        return
    end

    -- 免許確認後の貸出処理(Tier2-06参照)
end)

注意点・よくあるミス

  • チェックポイントの通過判定を「次に通過すべき番号」をserver側でも把握する設計にしないと(上記コード例は簡略化のためclient側のみで管理していますが、不正防止を厳密にするなら合格判定と同様にserver側でも検証してください)、順番を飛ばして最後のチェックポイントだけ踏んで合格にしてしまう不正が可能になります。
  • 免許の有無をチェックする関数(hasLicense)は、レンタカーや車両購入等、免許が必要なあらゆる機能で共通して呼び出せるようにしておくと、後から機能を追加しやすくなります。
  • 試験中に切断した場合、testActiveフラグがリセットされないままになる可能性があります。Tier2-15のplayerDroppedと組み合わせて後片付けすることを検討してください。

補足

より本格的に作り込む場合は、コース逸脱の検知(チェックポイント以外のルートを大きく外れたら失格にする)や、他車両との接触判定(減点方式)なども考えられます。免許の種類を複数用意する場合(普通免許・大型免許等)は、driver_licensesテーブルにlicense_type列を追加する設計に拡張してください。
