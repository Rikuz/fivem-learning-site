キャッシュ戦略

結論

このレッスンを終えると、頻繁に参照する変化の少ないデータをメモリ上に保持し、同じ内容のDB問い合わせを繰り返さない設計ができるようになります。

こんな時に使う: ショップの商品リストや設定値のように「めったに変わらないが、何度も参照される」データを扱うとき。

説明

DBへの問い合わせ(Tier3-03)は、Luaのテーブル操作に比べてずっと時間がかかります。プレイヤーが操作するたびに同じデータをDBから毎回取得していると、無駄な待ち時間・DB負荷が発生します。キャッシュ(一度取得したデータをメモリ上に保持し、次回以降はそこから読む仕組み)を使うことで、この無駄を減らせます。

コード例

server.lua: シンプルなキャッシュの実装

local shopItemsCache = nil

local function getShopItems(callback)
    if shopItemsCache then
        -- キャッシュがあれば、DBに問い合わせずそのまま返す
        callback(shopItemsCache)
        return
    end

    MySQL.Async.fetchAll('SELECT * FROM shop_items', {}, function(result)
        shopItemsCache = result -- 取得結果をキャッシュに保存する
        callback(result)
    end)
end

RegisterCommand('showshop', function()
    getShopItems(function(items)
        print(('商品数: %d'):format(#items))
    end)
end, false)

キャッシュを無効化する(データが更新されたとき)

local function addShopItem(name, price)
    MySQL.Async.execute('INSERT INTO shop_items (name, price) VALUES (@name, @price)', {
        ['@name'] = name,
        ['@price'] = price
    }, function()
        shopItemsCache = nil -- データが変わったのでキャッシュを破棄し、次回は再取得させる
    end)
end

一定時間で自動的に古くする(TTLキャッシュ)

local cache = { data = nil, expiresAt = 0 }
local CACHE_DURATION_MS = 60 * 1000 -- 1分間キャッシュを有効とする

local function getShopItemsWithTTL(callback)
    if cache.data and GetGameTimer() < cache.expiresAt then
        callback(cache.data)
        return
    end

    MySQL.Async.fetchAll('SELECT * FROM shop_items', {}, function(result)
        cache.data = result
        cache.expiresAt = GetGameTimer() + CACHE_DURATION_MS
        callback(result)
    end)
end

注意点・よくあるミス

  • キャッシュを無効化(破棄)する処理を書き忘れると、DB上のデータを更新したのに古いキャッシュがいつまでも返され続ける「データの不整合」が起きます。データを変更する処理には、必ずキャッシュのクリアもセットで書いてください。
  • プレイヤー固有のデータ(所持金など)を安易にキャッシュすると、複数のリクエストが同時に来た際に古い値をもとに計算してしまう競合(レースコンディション)が起きやすくなります。頻繁に変化するデータのキャッシュは慎重に設計してください。
  • 「めったに変わらないデータ」以外を無闇にキャッシュしないことも重要です。キャッシュは万能ではなく、複雑さとのトレードオフです。

補足

本格的な運用では、複数のresource間でキャッシュを共有したい場合にRedisのような外部のキャッシュサーバーを使うこともありますが、単一resource内であれば、このレッスンのようなシンプルなLuaテーブルによるキャッシュで十分なケースがほとんどです。
