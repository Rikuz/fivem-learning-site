ガレージシステムの基礎設計

結論

このレッスンを終えると、プレイヤーが所有する車両をDBに記録し、ガレージで出し入れ(格納・出庫)できる基本的な仕組みを実装できるようになります。

こんな時に使う: 自分の車を保管しておきたい、複数の車両を切り替えて使いたい、車両購入システム(Tier4-12)の受け皿としたいとき。

説明

ガレージシステムの核となる考え方は、「車両はDB上に存在するデータであり、実際にワールドに出ている車両(Tier2-06)はその一時的な表現にすぎない」というものです。格納中はDBの行として存在するだけで、ワールドには実体を作りません。

コード例

テーブル設計の例

# owned_vehicles テーブル
# id | identifier | model      | plate     | garage    | stored
# 1  | abc123     | adder      | MYCAR01   | legion    | true

server.lua: 車両を購入してDBに登録する

local function registerOwnedVehicle(identifier, model, plate, garage)
    MySQL.Async.execute(
        'INSERT INTO owned_vehicles (identifier, model, plate, garage, stored) VALUES (@id, @model, @plate, @garage, 1)',
        { ['@id'] = identifier, ['@model'] = model, ['@plate'] = plate, ['@garage'] = garage }
    )
end

server.lua: ガレージの所有車両一覧を取得する

RegisterNetEvent('garage:requestVehicles')
AddEventHandler('garage:requestVehicles', function(garageName)
    local playerId = source
    local identifier = GetPlayerIdentifiers(playerId)[1]

    MySQL.Async.fetchAll('SELECT * FROM owned_vehicles WHERE identifier = @id AND garage = @garage', {
        ['@id'] = identifier,
        ['@garage'] = garageName
    }, function(vehicles)
        TriggerClientEvent('garage:showVehicleList', playerId, vehicles)
    end)
end)

client.lua: 選んだ車両を出庫する

RegisterNetEvent('garage:spawnVehicle')
AddEventHandler('garage:spawnVehicle', function(vehicleData, spawnCoords)
    -- 変数のハッシュ化にはバッククォート記法が使えないため、GetHashKeyを使う(Tier1-11参照)
    local model = GetHashKey(vehicleData.model)
    RequestModel(model)
    while not HasModelLoaded(model) do Wait(0) end

    local vehicle = CreateVehicle(model, spawnCoords.x, spawnCoords.y, spawnCoords.z, spawnCoords.w, true, false)
    SetVehicleNumberPlateText(vehicle, vehicleData.plate)

    TriggerServerEvent('garage:markAsStored', vehicleData.id, false) -- storedフラグをfalseに更新
end)

注意点・よくあるミス

  • 「格納済み(stored = true)」の車両を、出庫処理をせずにもう一度出そうとすると、同じ車両が複数体存在してしまう(複製バグ)ことがあります。出庫時に必ずstoredフラグを確認・更新してください。
  • プレイヤーが車両に乗ったまま切断した場合の扱い(自動的に格納するか、その場に残すか)を決めておかないと、車両が野ざらしのままDBの状態と食い違うことがあります。Tier2-15「切断理由の取得と後処理」と組み合わせて設計してください。
  • 車両の色・カスタムパーツ(Tier2-14のダメージ管理とは別の見た目のカスタム)まで保存したい場合は、追加のカラムやJSON列(Tier3-17参照)が必要になります。

補足

ガレージの「どこから出すか」の座標選択や、複数ガレージ間での移動などは、要件に応じて発展させていく部分です。まずは「1つのガレージに、DBの車両を出し入れする」という最小限の流れを固めることが大切です。
