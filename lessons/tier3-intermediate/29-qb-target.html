qb-targetでインタラクションを作る

結論

このレッスンを終えると、ox_target(Tier3-07)の代替としてよく使われるqb-targetで、同じようなインタラクションゾーンを作ることができるようになります。

こんな時に使う: 導入しているサーバーがQBCoreベースで、qb-target系のリソースが標準になっているとき(ox_targetとqb-targetは似た役割のライブラリで、どちらか一方を選んで使います)。

説明

qb-targetはox_targetと同じ「third-eye」型のターゲティングライブラリですが、export名や引数の形が異なります。QBCoreエコシステムに合わせて作られており、jobによる表示制限などQBCore特有のオプションも用意されています。

コード例

ボックス型のゾーンを追加する

exports['qb-target']:AddBoxZone("MissionRowDutyClipboard", vector3(441.7989, -982.0529, 30.67834), 0.45, 0.35, {
    name = "MissionRowDutyClipboard",
    heading = 11.0,
    debugPoly = false,
    minZ = 30.77834,
    maxZ = 30.87834,
}, {
    options = {
        {
            type = "client",
            event = "myscript:openClipboard",
            icon = "fas fa-clipboard",
            label = "クリップボードを見る",
            job = "police", -- この職業のプレイヤーにしか表示しない(省略可)
        },
    },
    distance = 2.5
})

client.lua: 選択されたイベントを受け取る

RegisterNetEvent('myscript:openClipboard')
AddEventHandler('myscript:openClipboard', function()
    print('クリップボードを開く処理をここに書く')
end)

注意点・よくあるミス

  • AddBoxZoneの第1引数(ゾーン名)と第7引数のテーブル内nameは同じ値にするのが基本です(ゾーンの識別に使われます)。
  • ox_targetとqb-targetを同時に導入するのは避けてください。どちらもプレイヤーの照準を監視する処理を持っており、両方動かすと余計な負荷がかかったり、UIが二重に出たりする原因になります。サーバー全体でどちらか一方に統一しましょう。
  • type = "client"とtype = "server"で、発火するイベントの実行場所が変わります。お金の増減などサーバー権威が必要な処理を直接type = "client"のイベントに書かないよう注意してください(Tier3-05参照)。

補足

AddTargetModel(モデル指定)、AddTargetEntity(エンティティ指定)、RemoveZoneといった関数もox_targetのaddModel/addEntity/removeZoneに相当する機能として用意されています。基本的な設計思想はox_targetと共通しているため、片方を理解していればもう片方も習得しやすいはずです。
