音声近接チャットの考え方

結論

このレッスンを終えると、pma-voiceのような近接ボイスチャットリソースが、どのような仕組みで「近くにいる人にだけ声が届く」を実現しているかを理解できるようになります。

こんな時に使う: ボイスチャットリソースを導入する前に仕組みを理解しておきたい、無線システム(Tier3-28)を自作する前提知識として学びたいとき。

説明

FiveMのゲームエンジン自体には、Discordのようなボイスチャット機能は組み込まれていません。近接ボイスチャットは、Mumble(FiveMに統合されている音声通信プロトコル)の仕組みを、resource側からnative関数で制御することで実現されています。

基本的な考え方は次の3ステップです。①プレイヤーの座標を継続的に把握する、②距離に応じて音量を計算する(近いほど大きく、一定距離を超えたら聞こえなくする)、③MumbleSetVolumeOverrideのようなnative関数で、プレイヤーごとの音量を個別に設定する。

コード例

client.lua: 距離に応じてボイスの音量を調整する概念

local MAX_VOICE_DISTANCE = 15.0

CreateThread(function()
    while true do
        Wait(500)
        local myCoords = GetEntityCoords(PlayerPedId())

        for _, playerId in ipairs(GetActivePlayers()) do
            if playerId ~= PlayerId() then
                local targetPed = GetPlayerPed(playerId)
                local targetCoords = GetEntityCoords(targetPed)
                local distance = #(myCoords - targetCoords)

                if distance <= MAX_VOICE_DISTANCE then
                    -- 距離に応じて0.0(無音)〜1.0(最大)の音量を計算する
                    local volume = 1.0 - (distance / MAX_VOICE_DISTANCE)
                    -- MumbleSetVolumeOverride(playerId, volume) のようなnativeで反映する(概念的な例)
                else
                    -- 範囲外のプレイヤーの音量を0にする
                end
            end
        end
    end
end)

注意点・よくあるミス

  • 実際のMumble制御用native関数(MumbleSetVolumeOverride等)は細かい仕様・引数がバージョンによって異なることがあるため、このレッスンでは考え方の解説にとどめています。実装する際は、実績のあるpma-voiceのようなリソースを導入するのが現実的です(自作するとバグの発生源になりやすい領域です)。
  • 音量計算を毎フレーム(Wait(0))で全プレイヤー分行うと負荷が高くなります。上記コード例のように間隔を空けて計算するのが基本です(Tier5-01参照)。
  • ボイスチャットは音声データそのものを扱う特殊な領域のため、一般的なLuaスクリプトだけで完全に自作するのは難易度が非常に高い分野です。

補足

実運用では、pma-voice・saltychat・tokovoipのような実績あるボイスチャットリソースを導入し、その設定・連携方法を学ぶ方が現実的です。このレッスンは「中で何が起きているか」を理解するための土台として位置づけてください。
