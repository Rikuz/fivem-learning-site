自動販売機・ショップシステム

結論

このレッスンを終えると、商品リストを定義し、所持金を確認してから購入処理を行う、自動販売機やショップの基本的な仕組みを実装できるようになります。

こんな時に使う: 自動販売機で飲み物を買えるようにしたい、雑貨屋・武器屋のようなNPC店舗を作りたいとき(Tier4-03のokokTextUIや、Tier3-07のox_targetと組み合わせて店員とのインタラクションを作ることもできます)。

説明

この仕組みは、これまで学んだ要素の組み合わせです。Tier1-09のConfig設計で商品リストを定義し、Tier3-05のサーバー側バリデーションで所持金・在庫を確認し、Tier3-04のインベントリ操作で商品を渡します。

コード例

Config.lua: 商品リスト

Config.VendingItems = {
    { name = 'water', label = '水', price = 20 },
    { name = 'chips', label = 'ポテトチップス', price = 35 },
}

server.lua: 購入処理

local function findVendingItem(itemName)
    for _, item in ipairs(Config.VendingItems) do
        if item.name == itemName then
            return item
        end
    end
    return nil
end

RegisterNetEvent('vending:purchase')
AddEventHandler('vending:purchase', function(itemName)
    local playerId = source
    local item = findVendingItem(itemName)

    if not item then return end -- 存在しない商品名は無視する(Tier3-05参照)

    -- ESX/QBCore等、実際に導入しているフレームワークの所持金取得関数に置き換える(Tier4-01参照)
    local playerMoney = getPlayerMoney(playerId)

    if playerMoney < item.price then
        TriggerClientEvent('myscript:notify', playerId, '所持金が足りません')
        return
    end

    removePlayerMoney(playerId, item.price)
    exports.ox_inventory:AddItem(playerId, item.name, 1)
    TriggerClientEvent('myscript:notify', playerId, ('%sを購入しました'):format(item.label))
end)

client.lua: ox_targetで自動販売機にインタラクションを追加する

exports.ox_target:addModel('prop_vend_soda_01', {
    {
        name = 'use_vending_machine',
        icon = 'fa-solid fa-cart-shopping',
        label = '飲み物を買う',
        onSelect = function()
            TriggerServerEvent('vending:purchase', 'water')
        end,
    }
})

注意点・よくあるミス

  • Tier3-05で学んだ通り、商品の価格はclientから送らせず、server側のConfig.VendingItemsの値だけを使ってください。clientからは「どの商品を選んだか」という商品名だけを送らせます。
  • 在庫管理をしたい場合(自動販売機の中身が有限)は、商品ごとの残数をDBまたはメモリで管理し、購入のたびに減らす処理を追加する必要があります。
  • 1つの自動販売機モデルに対してaddModelを使うと、ワールド上の同じモデルの自動販売機全てにこのインタラクションが付きます。特定の1台だけに付けたい場合はaddLocalEntity/addEntity(Tier3-07参照)を使ってください。

補足

プレイヤーが経営する店舗(Tier4-10のビジネス口座と連携する形)にしたい場合は、商品リストと売上を組織口座に紐付ける設計に発展させることもできます。
