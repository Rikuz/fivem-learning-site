Gitでのバージョン管理

結論

このレッスンを終えると、自分のresourceフォルダの変更履歴をGitで管理し、いつでも過去の状態に戻せるようになります。

こんな時に使う: 「昨日まで動いていたのに、今日変更したら壊れた」というときに、変更前の状態に戻したいとき。複数人で同じスクリプトを編集するとき。

説明

Git(ファイルの変更履歴を記録・管理するバージョン管理システム)を使うと、「いつ・どのファイルの・どこを変更したか」が全て記録され、必要になれば過去の状態に戻せます。resourceフォルダ単位でGit管理するのが一般的です。

コード例

Gitリポジトリを初期化する

cd C:\fxserver\resources\[local]\my-first-script
git init

.gitignoreを作成する(記録しないファイルを指定)

# .gitignore
node_modules/
*.log
.env

.gitignore(Gitの記録対象から除外するファイル・フォルダを指定する設定ファイル)を用意しておくと、ビルド成果物や個人の設定ファイルなど、共有すべきでないファイルを誤ってコミットせずに済みます。

変更を記録する(コミット)

git add fxmanifest.lua client.lua server.lua
git commit -m "最初のスクリプトを作成"

変更履歴を確認する

git log --oneline

特定のコミット時点まで戻す

# 直前のコミットに戻す(作業中の変更は破棄される点に注意)
git checkout -- .

# 特定のコミットの内容を確認する
git show <コミットハッシュ>

注意点・よくあるミス

  • git addし忘れたファイルはコミットに含まれません。git statusで「変更されたが記録されていないファイル」を確認する癖をつけましょう。
  • ライセンスキーやDBパスワードなど、秘密情報を含むファイルを誤ってコミットしないよう注意してください(.gitignoreで除外するか、環境変数化する)。一度公開リポジトリにpushしてしまうと、削除しても履歴に残り続けます。
  • git checkout -- .のような変更破棄コマンドは取り消せません。実行前に本当に破棄してよい変更か確認してください。

補足

GitHubのようなリモートリポジトリサービスと組み合わせれば、複数人での共同開発やバックアップにも使えます(このサイト自体もGitHub Pagesで公開されており、同じ仕組みを使っています)。まずは自分のPC内だけでコミットする習慣から始めるのがおすすめです。
