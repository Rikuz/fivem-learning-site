server.cfgの全体構造

結論

このレッスンを終えると、server.cfgに書く各命令(set/setr/sets/ensure等)の意味と読み込み順序を理解し、設定ファイルを見て何が起きるか読み解けるようになります。これまでのレッスンで断片的に触れてきたensureやsetを、ここで体系的に整理します。

説明

server.cfgはFiveMサーバー起動時に上から順番に実行される、設定コマンドの羅列です。行の順番そのものに意味があり(後の行が前の行の設定を上書きする、resourceは書かれた順に起動する等)、闇雲にコピペすると意図しない挙動になることがあります。

コード例

典型的なserver.cfgの構成

# 1. ネットワーク設定(最初に書くのが一般的)
endpoint_add_tcp "0.0.0.0:30120"
endpoint_add_udp "0.0.0.0:30120"

# 2. サーバー基本情報
set sv_hostname "My Local Dev Server"
set sv_maxclients 32
sv_licenseKey "自分のライセンスキー"

# 3. リソースの起動(書いた順に実行される)
ensure mapmanager
ensure chat
ensure spawnmanager
ensure oxmysql
ensure ox_lib
ensure my-first-script    # 依存先(oxmysql等)より後ろに書く

# 4. カスタム設定(自作resourceが参照する値)
set my_script:welcome_message "ようこそ!"

# 5. 別ファイルを読み込む(分割管理)
exec permissions.cfg

set / setr / sets の違い

set my_convar "値"    # サーバー内部でのみ参照できる(clientからは見えない)
setr my_convar "値"   # 読み取り専用として、clientにもレプリケート(複製)される
sets my_convar "値"   # clientからも変更可能な状態でレプリケートされる(通常はほぼ使わない)

スクリプト側でconvarを読み取る

local message = GetConvar('my_script:welcome_message', 'デフォルトのメッセージ')
print(message)

注意点・よくあるミス

  • ensureは書かれた順に実行され、依存先を先に起動する必要があります。ensure my-first-scriptをensure oxmysqlより前に書くと、my-first-scriptがoxmysqlのexportを見つけられずエラーになることがあります(Tier1-04のdependencyと合わせて対策できますが、server.cfgの順序自体も意識してください)。
  • 同じconvarを複数回setすると、後に書いた方が有効になります。execで別ファイルを読み込む場合、読み込みタイミングにも注意してください。
  • sv_licenseKeyのような秘密情報を含むserver.cfgを、Tier1-08で学んだGitでそのまま公開リポジトリにコミットしないよう注意してください。

補足

exec 別ファイル.cfgを使うと、権限設定(ACE)やリソース一覧などを目的別に分割し、見通しを良くできます(Tier2-04で扱ったadd_aceもserver.cfgまたはexecされたファイルに書きます)。
