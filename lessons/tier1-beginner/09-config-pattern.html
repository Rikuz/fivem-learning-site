Config.luaの設計パターン

結論

このレッスンを終えると、変更されやすい値(価格・座標・時間など)を1つの設定ファイルにまとめ、コードの他の部分から安全に参照する設計ができるようになります。

こんな時に使う: ショップの価格を後から調整したい、座標を複数の場所で使い回したい、サーバーごとに設定を変えられるようにしたいとき。

説明

座標や価格などの値をコードのあちこちに直接書いてしまう(ハードコーディングする)と、後で変更するときに全箇所を探して直す必要が出てきます。Config.luaという1つのファイルに設定値をまとめ、shared_script(Tier1-04参照)として読み込むことで、修正箇所を1つに集約できます。

コード例

Config.lua

Config = {}

Config.ShopLocation = vector3(100.0, 200.0, 30.0)
Config.ShopItems = {
    { name = 'water', label = '水', price = 20 },
    { name = 'bread', label = 'パン', price = 30 },
}
Config.RestockIntervalMinutes = 30

fxmanifest.lua

shared_script 'config.lua' -- client/serverどちらからも参照できるようにする

client_script 'client.lua'
server_script 'server.lua'

他のファイルからConfigを参照する

-- server.lua
RegisterNetEvent('myscript:buyItem')
AddEventHandler('myscript:buyItem', function(itemName)
    for _, item in ipairs(Config.ShopItems) do
        if item.name == itemName then
            print(('%sの価格は%s円です'):format(item.label, item.price))
            return
        end
    end
end)

注意点・よくあるミス

  • Config.luaをshared_scriptにし忘れてclient_scriptだけに指定すると、server側からConfigを参照した際にnilエラーになります。
  • Config = {}のようにグローバル変数として定義するのが一般的ですが、他のresourceのConfigと名前が衝突しないよう注意してください(1つのresource内で完結していれば問題ありません)。
  • 設定値を変更しただけでは反映されません。Tier1-03で学んだようにrestart リソース名でresourceを再起動する必要があります。

補足

大規模なリソースではconfig/items.lua、config/locations.luaのように用途ごとにConfigファイルを分割することもあります(Tier2-19「shared_scriptを使ったモジュール分割」で発展的に扱います)。
