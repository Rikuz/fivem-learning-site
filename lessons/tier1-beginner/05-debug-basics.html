デバッグの基本

結論

このレッスンを終えると、F8コンソールでエラーメッセージを読み、どのファイルの何行目が原因かを特定し、print()で原因を絞り込むという、開発の基本サイクルができるようになります。

説明

FiveMではclient側のエラーはF8コンソール(ゲーム内でF8キーを押すと開発者コンソールが開く)に、server側のエラーはFXServerを起動しているターミナル(コンソールウィンドウ)に表示されます。

エラーメッセージには通常、ファイル名と行番号が含まれています。まずここを確認するのがデバッグの第一歩です。

コード例

典型的なエラーメッセージの例

SCRIPT ERROR: @my-first-script/client.lua:5: attempt to index a nil value (global 'playre')

これは「my-first-scriptリソースのclient.luaの5行目で、playreという(定義されていない)変数を使おうとした」というエラーです。多くの場合、変数名のタイプミス(この例ではplayerのつづり間違い)が原因です。

print()で状態を確認する

local function calculateReward(level)
    print('calculateReward called with level =', level) -- 引数が正しく渡っているか確認

    local reward = level * 100
    print('reward =', reward) -- 計算結果を確認

    return reward
end

calculateReward(5)

処理の要所要所にprint()を挟むことで、「どこまでは正しく動いていて、どこから想定と違う値になっているか」を絞り込めます。原因箇所が特定できたら、デバッグ用のprint()は削除するか、コメントアウトしておきましょう。

注意点・よくあるミス

  • client側のエラーはF8コンソール、server側のエラーはターミナル(サーバーを起動している画面)と、表示される場所が違います。片方だけ見て「エラーが出ていない」と勘違いしないよう注意してください。
  • エラーメッセージの1行目だけでなく、その下に続く「スタックトレース」(処理がどの関数からどの関数へ呼ばれて到達したかの履歴)も、原因特定の手がかりになります。
  • print()を大量に残したままにすると、後で本当に必要なログが埋もれてしまいます。確認が終わったら整理する習慣をつけましょう。

補足

F8コンソールではresmon 1と入力するとリソースごとの負荷(CPU使用率)を表示できます。これはTier5「パフォーマンス計測と最適化」で詳しく扱います。エラーが出た際は、まず落ち着いてファイル名・行番号を確認する癖をつけることが、上達への一番の近道です。
