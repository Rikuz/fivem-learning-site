Renewed-Bankingと連携する

結論

このレッスンを終えると、Tier4-06で扱ったokokBankingV2以外の選択肢として、Renewed-Banking(コミュニティで人気の銀行システム)と連携することができるようになります。

こんな時に使う: 導入しているサーバーがokokBankingではなくRenewed-Bankingを採用しているとき。銀行スクリプトを乗り換える際にexportの違いを把握したいとき。

説明

Renewed-Bankingは、okokBankingV2と同じく口座残高の取得・入出金・取引記録を扱いますが、exportの名前が異なります。両者は役割は同じでも構文に互換性はないため、どちらを導入しているかを確認してから正しいexport名を使う必要があります。

コード例

残高を取得する

-- 存在しない口座の場合はfalseが返る
local amount = exports['Renewed-Banking']:getAccountMoney(account)

if amount then
    print(('口座残高: $%s'):format(amount))
end

入金・出金する

local depositSuccess = exports['Renewed-Banking']:addAccountMoney(account, 500)
local withdrawSuccess = exports['Renewed-Banking']:removeAccountMoney(account, 200)

if not withdrawSuccess then
    print('出金に失敗しました(残高不足の可能性があります)')
end

職業(job)ごとの組織口座を作成する

exports['Renewed-Banking']:CreateJobAccount({ name = 'mechanic', label = '整備工場' }, 5000)
-- 第1引数: job名・表示名を含むテーブル、第2引数: 初期残高

Tier4-10「ビジネス/組織口座の管理」のokokBanking版との比較

-- okokBankingV2の場合(Tier4-06参照)
exports['okokBanking']:AddMoney(society, value)

-- Renewed-Bankingの場合
exports['Renewed-Banking']:addAccountMoney(account, value)
-- 「入金する」という同じ操作でも、exportの名前も引数の順序も異なる点に注意

注意点・よくあるミス

  • okokBanking用に書いたコードをそのまま使い回すと、exportのリソース名('okokBanking' vs 'Renewed-Banking')も関数名も違うため動きません。どちらの銀行スクリプトを導入しているか、必ず事前に確認してください。
  • 両方の銀行スクリプトを同時に導入するのは避けてください。プレイヤーの所持金が2つのシステムに分散し、整合性が取れなくなります。
  • getAccountMoneyは口座が存在しない場合falseを返します。数値として扱う前に、必ずこの戻り値を確認してください。

補足

本レッスンのexport構文(getAccountMoney、addAccountMoney、removeAccountMoney、CreateJobAccount)は公式ドキュメント(renewed.dev/banking/exports)で確認済みです。qb-managementからの移行用にexports['qb-management']:AddMoneyをexports['Renewed-Banking']:addAccountMoneyに読み替える互換情報も公式に案内されています。バージョンによって仕様が変わる場合があるため、公式ドキュメントを確認してください。
