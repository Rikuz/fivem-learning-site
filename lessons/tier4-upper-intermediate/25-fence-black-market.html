故売/闇市場(fence NPC)システム

結論

このレッスンを終えると、盗品や違法な品物を専門のNPC(故売屋/fence)に売却して現金化する仕組みを作れるようになります。Tier3-26の一般的なショップとは逆方向の「プレイヤーからNPCに売る」フローです。

こんな時に使う: 演習ex-10の薬物生産チェーンの完成品を換金したい、盗んだ貴金属や電子機器を売却できるようにしたいとき。

説明

故売屋(fence)は、正規のショップと違い「特定の品物だけ、正規の店より安い/変動する価格で買い取る」NPCです。Tier3-07のox_targetでインタラクションを追加し、Tier3-04/Tier3-30のアイテム操作で所持品を確認・削除、お金を付与するという組み合わせで実装します。

コード例

Config.lua: 買取品目と価格

Config.FenceItems = {
    { name = 'stolen_jewelry', label = '盗んだ宝石', basePrice = 300 },
    { name = 'stolen_electronics', label = '盗んだ電子機器', basePrice = 150 },
    { name = 'processed_drugs', label = '精製済みの違法薬物', basePrice = 500 }, -- 演習ex-10の完成品
}

server.lua: 売却処理

local function findFenceItem(itemName)
    for _, item in ipairs(Config.FenceItems) do
        if item.name == itemName then return item end
    end
    return nil
end

RegisterNetEvent('fence:sellItem')
AddEventHandler('fence:sellItem', function(itemName, amount)
    local playerId = source
    local item = findFenceItem(itemName)

    if not item or not amount or amount < 1 then return end

    local count = exports.ox_inventory:GetItemCount(playerId, itemName)
    if count < amount then
        TriggerClientEvent('myscript:notify', playerId, '所持していません', 'error')
        return
    end

    -- 買取価格を少し変動させる(毎回同じ額にしない)
    local priceMultiplier = 0.8 + (math.random() * 0.4) -- 0.8〜1.2倍
    local totalPrice = math.floor(item.basePrice * amount * priceMultiplier)

    exports.ox_inventory:RemoveItem(playerId, itemName, amount)
    addPlayerMoney(playerId, totalPrice) -- Tier4-01のフレームワーク連携で実装する想定

    TriggerClientEvent('myscript:notify', playerId, ('$%sで売却しました'):format(totalPrice), 'success')

    -- 犯罪行為として指名手配度を上げる(Tier4-24参照)
    exports['my-wanted-system']:AddWantedLevel(playerId, 5, '故売')
end)

client.lua: ox_targetでfence NPCにインタラクションを追加する

exports.ox_target:addModel('g_m_y_mexgoon_01', {
    {
        name = 'sell_to_fence',
        icon = 'fa-solid fa-money-bill-transfer',
        label = '売却する',
        onSelect = function()
            TriggerServerEvent('fence:sellItem', 'stolen_jewelry', 1)
        end,
    }
})

注意点・よくあるミス

  • 買取品目はTier3-05のバリデーションと同じく、必ずserver側のConfig.FenceItemsだけを信用してください。clientから任意のアイテム名・金額を送らせて計算させてはいけません。
  • 所持数の確認(GetItemCount)と削除(RemoveItem)の間に別の処理が割り込まないよう、一連の処理を1つのイベントハンドラ内で完結させてください(Tier5-02の競合状態の考え方)。
  • 故売行為も指名手配度(Tier4-24)を上げる犯罪行為の1つとして扱うのが自然です。加算を忘れないようにしましょう。

補足

買取価格を完全固定にせず、上記コード例のように毎回わずかに変動させることで、単調な作業感を減らせます。さらに発展させる場合は、「一定時間内に売りすぎると買取価格が下がる」といった需給バランスの仕組みも考えられます。
