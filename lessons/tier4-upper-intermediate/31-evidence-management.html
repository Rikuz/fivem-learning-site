証拠品・押収品管理

結論

このレッスンを終えると、逮捕時に押収したアイテムを警察専用の保管庫(evidence bag)に記録し、いつ・誰が・何を押収したかを事件番号(ケースID)ごとに管理できるようになります。Tier3-37で学んだRegisterStashの応用と、oxmysqlでの記録を組み合わせます。

こんな時に使う: 逮捕(Tier4-29)や投獄(Tier4-30)の際に押収した違法薬物・盗品を、警察側が後から確認・処分できる形で保管したいとき。

説明

証拠品管理は「①アイテムの実体(所持品としての在庫)」と「②いつ誰が何を押収したかという記録(ログ)」の2つを分けて考えると設計しやすくなります。①はTier3-37のRegisterStashで警察専用のスタッシュを用意することで実現し、②は自作のDBテーブル(evidence_log)にオートセーブ(Tier3-15)と同じ考え方で記録します。

コード例

server.lua: 証拠品保管庫をJobで制限して登録する(Tier3-37参照)

CreateThread(function()
    -- RegisterStash(id, label, slots, weight, owner, groups)
    -- owner=falseで共有、groups={ police = 0 }でpolice Jobのみアクセス可能にする
    exports.ox_inventory:RegisterStash('police_evidence', '警察の証拠品保管庫', 100, 500000, false, { police = 0 })
end)

SQL: 押収記録用テーブル(自作、evidence_log)

CREATE TABLE IF NOT EXISTS `evidence_log` (
  `id` INT AUTO_INCREMENT PRIMARY KEY,
  `case_id` VARCHAR(50) NOT NULL,
  `item_name` VARCHAR(50) NOT NULL,
  `amount` INT NOT NULL,
  `officer_identifier` VARCHAR(64) NOT NULL,
  `suspect_identifier` VARCHAR(64) NOT NULL,
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP
);

server.lua: 押収処理(対象から没収し、保管庫に入れ、ログを残す)

RegisterNetEvent('evidence:seizeItem')
AddEventHandler('evidence:seizeItem', function(targetId, itemName, amount, caseId)
    local officerId = source

    if not IsPlayerAceAllowed(officerId, 'job.police') then return end

    local count = exports.ox_inventory:GetItemCount(targetId, itemName)
    if not amount or amount < 1 or count < amount then
        TriggerClientEvent('myscript:notify', officerId, '対象がそのアイテムを十分に所持していません', 'error')
        return
    end

    -- 対象から没収する(Tier3-30のアイテム操作)
    exports.ox_inventory:RemoveItem(targetId, itemName, amount)

    -- 証拠品保管庫に入れる(RegisterStashで登録したスタッシュのidを指定する)
    -- ※スタッシュへの直接AddItemは公式ドキュメントの表記通りに動作するはずですが、
    --   バージョンによって差異が出る可能性があるため、導入時は必ず動作確認してください。
    exports.ox_inventory:AddItem('police_evidence', itemName, amount)

    -- 押収記録をDBに残す(Tier3-32のモダンAPI)
    local officerIdentifier = GetPlayerIdentifierByType(officerId, 'license') -- Tier4-13のGetPlayerIdentifiers参照
    local suspectIdentifier = GetPlayerIdentifierByType(targetId, 'license')

    MySQL.insert('INSERT INTO evidence_log (case_id, item_name, amount, officer_identifier, suspect_identifier) VALUES (?, ?, ?, ?, ?)', {
        caseId, itemName, amount, officerIdentifier, suspectIdentifier
    })

    TriggerClientEvent('myscript:notify', officerId, ('%sを%d個押収しました(ケース: %s)'):format(itemName, amount, caseId), 'success')
end)

server.lua: ケースIDで押収履歴を検索する(MDT連携)

RegisterNUICallback('mdt:searchEvidence', function(data, cb)
    local records = MySQL.query.await('SELECT * FROM evidence_log WHERE case_id = ? ORDER BY created_at DESC', {
        data.caseId
    })

    cb(records or {})
end)

注意点・よくあるミス

  • 押収処理の権限チェック(job.police)は必ずserver側のevidence:seizeItemハンドラ内で行ってください。Tier3-20の管理者メニューと同じ注意点です。
  • police_evidenceスタッシュへのAddItemがバージョンによって想定通り動かない場合は、対象からRemoveItemした後、保管庫を開いた警察官が手動でアイテムをスタッシュにドラッグする運用に切り替えることも検討してください。
  • 押収記録(evidence_log)は個人の識別子を含む機微な情報です。Tier3-21の通報システムと同様、閲覧できる対象を警察官のみに限定してください。
  • ケースID(caseId)の発行ルールを事前に決めておかないと、押収記録がバラバラになり後から追跡できなくなります。逮捕時に自動採番する仕組み(例: 日付+連番)を用意するのがおすすめです。

補足

スタッシュへの直接AddItem呼び出しは、ox_inventoryのバージョンによって挙動が変わる可能性があるため、導入時は必ず動作確認と公式ドキュメント(overextended.dev)の確認を行ってください。これで演習ex-11「麻薬密売シンジケート」で使う、犯罪側・警察側の両方の主要な仕組みが揃いました。
