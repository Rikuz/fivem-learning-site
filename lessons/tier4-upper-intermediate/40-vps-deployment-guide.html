本番運用・VPSデプロイガイド

結論

このレッスンを終えると、ローカルPC上のtxAdmin環境から、実際にプレイヤーが接続できるVPS(レンタルサーバー)上へFXServerを移し、systemdによる自動再起動・定期バックアップまで含めた「公開に必要な最低限の運用」ができるようになります。Tier1-01でローカルサーバーの起動、Tier1-14でtxAdminの管理機能を扱いましたが、ここでは「実際に外部へ公開する」ための一段階を扱います。

説明

ローカルPCで動かしているFXServerは、自分のPCの電源が入っている間しか稼働せず、家庭用回線からの公開はポート開放や通信速度の面で現実的ではありません。そのため本番公開では、常時稼働するVPS(多くはUbuntu/DebianなどのLinux)上にFXServerを設置します。公式ドキュメント(docs.fivem.net)によると、Linux版は「Windows版が推奨で、Linuxはディストリビューションの互換性問題により提供されているcourtesy port(便宜的な移植)」と明記されているため、パフォーマンス上の問題が出た場合はWindows Serverでの運用も選択肢に入れてください。以下ではLinux VPSを例に手順を示します。

コード例

① FXServerアーティファクトの取得と展開(docs.fivem.netで確認済み)

# サーバーダウンロードページ(docs.fivem.net/docs/server-download/)で
# 推奨されているmasterブランチのLinux版URLをコピーし、wgetで取得する
mkdir -p ~/FXServer/server && cd ~/FXServer/server
wget https://runtime.fivem.net/artifacts/fivem/build_proot_linux/master/xxxxx-yyyyyyyy/fx.tar.xz
tar xf fx.tar.xz

# サーバーデータ(mapmanager等の基本resource一式)を別途取得する
git clone https://github.com/citizenfx/cfx-server-data.git ~/FXServer/server-data

アーティファクトのURLはビルドごとに変わるため、必ず公式のサーバーダウンロードページ(docs.fivem.net/docs/server-download/)で最新の推奨URLを確認してからwgetしてください。

② 最小構成のserver.cfg(docs.fivem.netで確認済み)

# ~/FXServer/server-data/server.cfg
endpoint_add_tcp "0.0.0.0:30120"
endpoint_add_udp "0.0.0.0:30120"

sv_hostname "自分のサーバー名"
sv_maxclients 48

# portal.cfx.re で無料登録したライセンスキーに必ず置き換える(changemeのままでは起動しない)
sv_licenseKey changeme

ensure mapmanager
ensure chat
ensure spawnmanager
ensure sessionmanager

# ここから下に自作リソースのensureを追加していく
# ensure my_script

③ サーバーの起動(docs.fivem.netで確認済み)

cd ~/FXServer/server-data
bash ~/FXServer/server/run.sh +exec server.cfg

④ systemdでの自動起動・自動再起動(一般的な運用パターン)

上記の起動コマンドをターミナルで実行したままにする方法では、SSH接続が切れるとサーバーも落ちてしまいます。Linuxサーバーの運用で広く使われているのが、systemdにサービスとして登録し、クラッシュ時や再起動時に自動で立ち上げ直す方法です。

# /etc/systemd/system/fivem.service
[Unit]
Description=FiveM FXServer
After=network.target

[Service]
Type=simple
User=fivem
WorkingDirectory=/home/fivem/FXServer/server-data
ExecStart=/bin/bash /home/fivem/FXServer/server/run.sh +exec server.cfg
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
# 反映・自動起動の有効化・起動
sudo systemctl daemon-reload
sudo systemctl enable fivem
sudo systemctl start fivem

# ログの確認
sudo journalctl -u fivem -f

注意点・よくあるミス

  • sv_licenseKeyをchangemeのまま公開しようとして起動に失敗する例が非常に多いです。必ずportal.cfx.reで無料のライセンスキーを取得し、置き換えてください。
  • ポート30120のTCP・UDP両方を、VPS側のファイアウォール(ufw等)と、クラウド事業者側のセキュリティグループ/ファイアウォール設定の両方で開放しないと、プレイヤーが接続できません。片方だけ開けて「繋がらない」と詰まるケースが多いです。
  • root権限で直接FXServerを常時稼働させるのは避け、上記例のように専用ユーザー(fivem等)で動かしてください。自作リソースに脆弱性があった場合の被害範囲を減らせます。
  • Tier1-14で扱ったtxAdminの自動バックアップは「バックアップを取ること」自体は自動化できますが、VPSそのものに障害が起きた場合に備えて、バックアップを別のサーバー・別のストレージ(S3等)にも定期的にコピーする運用を別途組んでください。VPS内に保存されたバックアップだけでは、VPS自体の消失に対応できません。

補足

Windows Serverで運用する場合は、公式ドキュメントのWindows向けセットアップ手順(server.cfgの内容自体はLinuxとほぼ共通)に従ってください。また、txAdminのWebパネル(Tier1-14参照)はLinux/Windowsどちらの環境でも同じように使えるため、systemd(または相当する仕組み)で自動起動さえ組んでおけば、日常的な運用(リソースの再起動・監視・バックアップ)はtxAdminのUIから行えます。

アーティファクトのURL・推奨OSバージョン・systemdの書き方はいずれも環境やFXServerのバージョンによって変わることがあります。本レッスンのコマンド・server.cfgの内容はdocs.fivem.netの公式ドキュメントで確認済みですが、実際にデプロイする際は最新の公式ドキュメントも必ず確認してください。
