中古車販売店(ディーラー)システム

結論

このレッスンを終えると、車両カタログの提示、試乗、購入処理、購入後の所有車両への登録という、ディーラーシステムの一連の流れを実装できるようになります。

こんな時に使う: プレイヤーが車を購入できるお店を作りたい、購入前に試乗できるようにしたいとき。

説明

ディーラーシステムは、これまで学んだ複数の要素の組み合わせです。Tier2-06の車両生成(試乗用)、Tier3-05のサーバー側バリデーション(購入処理)、Tier3-18のガレージシステム(購入後の車両をDBに登録)を統合します。

コード例

Config.lua: 販売車両カタログ

Config.DealershipCatalog = {
    { model = 'blista', label = 'Blista', price = 15000 },
    { model = 'adder',  label = 'Adder',  price = 1000000 },
}

client.lua: 試乗する(その場で生成し、購入はしない)

local testDriveVehicle = nil

local function startTestDrive(modelName)
    local model = GetHashKey(modelName) -- Tier1-11参照
    RequestModel(model)
    while not HasModelLoaded(model) do Wait(0) end

    local coords = GetEntityCoords(PlayerPedId())
    testDriveVehicle = CreateVehicle(model, coords.x + 5.0, coords.y, coords.z, 0.0, true, false)
    SetPedIntoVehicle(PlayerPedId(), testDriveVehicle, -1)
end

local function endTestDrive()
    if testDriveVehicle then
        SetEntityAsMissionEntity(testDriveVehicle, true, true)
        DeleteVehicle(testDriveVehicle)
        testDriveVehicle = nil
    end
end

server.lua: 購入処理(価格はserver側の定義のみ使用)

local function findCatalogEntry(model)
    for _, entry in ipairs(Config.DealershipCatalog) do
        if entry.model == model then return entry end
    end
    return nil
end

RegisterNetEvent('dealership:purchaseVehicle')
AddEventHandler('dealership:purchaseVehicle', function(model)
    local playerId = source
    local entry = findCatalogEntry(model)
    if not entry then return end

    local playerMoney = getPlayerMoney(playerId) -- Tier4-01のフレームワーク連携で取得
    if playerMoney < entry.price then
        TriggerClientEvent('myscript:notify', playerId, '所持金が足りません')
        return
    end

    removePlayerMoney(playerId, entry.price)

    local identifier = GetPlayerIdentifiers(playerId)[1]
    local plate = ('CAR%04d'):format(math.random(0, 9999))

    -- Tier3-18で作った関数を使い、所有車両として登録する
    registerOwnedVehicle(identifier, entry.model, plate, 'main_garage')

    TriggerClientEvent('myscript:notify', playerId, ('%sを購入しました!ガレージから出せます'):format(entry.label))
end)

注意点・よくあるミス

  • 試乗車と購入した車両は別のものとして扱ってください。試乗車をそのまま「購入完了」にしてしまうと、ナンバープレートや所有者情報の管理が破綻します。購入時はTier3-18のように新しくDBへ登録します。
  • 価格は必ずserver側のConfig.DealershipCatalogの値だけを使い、client側から金額を送らせないでください(Tier3-05参照)。
  • 試乗中にプレイヤーが遠くまで走り去ってしまうケースを想定し、一定時間や一定距離で強制的に試乗を終了させる処理を用意すると安全です。

補足

本格的なディーラーシステムでは、ローン(分割払い)機能をTier4-06のokokBankingV2のloan_createタイプと組み合わせて実装することもあります。
