分割払い(ローン)システム

結論

このレッスンを終えると、頭金+分割回数を指定して車両を購入し、定期的に自動で分割金が引き落とされるローンシステムを作れるようになります。Tier4-27のマネーロンダリングで扱った「時間経過で処理が進む」パターンの、経済システムへの応用です。

こんな時に使う: Tier4-12の中古車販売店で、車両価格が高額な場合に一括購入以外の選択肢を用意したいとき。

説明

ローンは「①頭金を先に支払う」「②残額を分割回数で割った金額を、一定間隔ごとに口座から自動で引き落とす」「③滞納した場合の扱いを決めておく」という3要素で設計します。引き落とし処理はサーバーが常に起動しているとは限らないため、「前回いつ支払ったか」をDBに記録し、resource起動時に未払い分をまとめて確認する設計にしておくと、再起動をまたいでも正しく動作します。

コード例

SQL: ローンテーブル

CREATE TABLE IF NOT EXISTS `vehicle_loans` (
  `id` INT AUTO_INCREMENT PRIMARY KEY,
  `owner_identifier` VARCHAR(64) NOT NULL,
  `plate` VARCHAR(12) NOT NULL,
  `remaining_amount` INT NOT NULL,
  `installment_amount` INT NOT NULL,
  `last_paid_at` DATETIME DEFAULT CURRENT_TIMESTAMP
);

server.lua: ローンを組んで購入する

local DOWN_PAYMENT_RATE = 0.2 -- 頭金は車両価格の20%

RegisterNetEvent('dealership:purchaseWithLoan')
AddEventHandler('dealership:purchaseWithLoan', function(vehiclePrice, plate, installmentCount)
    local playerId = source
    local identifier = GetPlayerIdentifierByType(playerId, 'license')

    if not installmentCount or installmentCount < 2 or installmentCount > 24 then
        TriggerClientEvent('myscript:notify', playerId, '分割回数は2〜24回で指定してください', 'error')
        return
    end

    local downPayment = math.floor(vehiclePrice * DOWN_PAYMENT_RATE)
    local paid = removePlayerMoney(playerId, downPayment) -- Tier4-01のフレームワーク連携で実装する想定
    if not paid then
        TriggerClientEvent('myscript:notify', playerId, '頭金分の所持金が足りません', 'error')
        return
    end

    local remaining = vehiclePrice - downPayment
    local installmentAmount = math.ceil(remaining / installmentCount)

    MySQL.insert('INSERT INTO vehicle_loans (owner_identifier, plate, remaining_amount, installment_amount) VALUES (?, ?, ?, ?)', {
        identifier, plate, remaining, installmentAmount
    })

    TriggerClientEvent('myscript:notify', playerId, ('頭金$%sで購入しました(残り$%sを%d回で分割払い)'):format(downPayment, remaining, installmentCount), 'success')
end)

server.lua: 定期的に分割金を引き落とす

local PAYMENT_INTERVAL_MS = 24 * 60 * 60 * 1000 -- 24時間ごとに引き落とす

CreateThread(function()
    while true do
        Wait(60 * 60 * 1000) -- 1時間おきに「支払い期限が来ていないか」を確認する

        local dueLoans = MySQL.query.await(
            'SELECT * FROM vehicle_loans WHERE remaining_amount > 0 AND last_paid_at <= DATE_SUB(NOW(), INTERVAL 1 DAY)', {}
        )

        for _, loan in ipairs(dueLoans or {}) do
            local playerId = getOnlinePlayerIdByIdentifier(loan.owner_identifier) -- Tier2-20の識別子とオンラインプレイヤーの紐付けを利用する想定

            if playerId then
                local amount = math.min(loan.installment_amount, loan.remaining_amount)
                local paid = removePlayerMoney(playerId, amount)

                if paid then
                    MySQL.update('UPDATE vehicle_loans SET remaining_amount = remaining_amount - ?, last_paid_at = NOW() WHERE id = ?', {
                        amount, loan.id
                    })
                    TriggerClientEvent('myscript:notify', playerId, ('車両ローンの分割金$%sが引き落とされました'):format(amount), 'success')
                else
                    -- 滞納。Tier4-24の指名手配度とは別に「信用スコア」等の仕組みを別途設計するのも一案
                    TriggerClientEvent('myscript:notify', playerId, '分割金の支払いに失敗しました(所持金不足)', 'error')
                end
            end
        end
    end
end)

注意点・よくあるミス

  • 頭金・分割回数の妥当性チェック(上記コード例のinstallmentCountの範囲確認)は必ずserver側で行ってください。clientから任意の回数・金額を送らせてはいけません(Tier3-05参照)。
  • プレイヤーがオフラインの間は引き落としができません。上記コード例はlast_paid_atを基準に「支払い期限が来ているか」をDB側で判定しているため、再ログイン後に自然と追いつく設計になっています。
  • 滞納が続いた場合の対応(車両の差し押さえ、信用情報への影響等)を決めずに実装すると、無限に滞納し続けられる抜け穴になります。ペナルティを必ず設計しておきましょう。

補足

上記コード例のgetOnlinePlayerIdByIdentifierは概念を示す関数名です。実際には、ログイン時にidentifierとプレイヤーIDの対応表をメモリ上に保持しておくなどの実装が必要です。これで車両ディーラートラックの主要機能(在庫・試乗・購入・分割払い)が揃いました。演習ex-16ではこれらを1つのディーラーresourceに統合します。
