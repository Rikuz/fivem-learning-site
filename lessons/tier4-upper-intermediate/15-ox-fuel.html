ox_fuelで燃料システムを連携する

結論

このレッスンを終えると、ox_fuel(FiveMの燃料システムリソース)の支払い方法を、自分のサーバーのフレームワークに合わせてカスタマイズすることができるようになります。

こんな時に使う: ガソリンスタンドで給油できるようにしたい、ESX/QBCore以外の独自フレームワークで所持金を管理していて、標準の支払い処理をそのまま使えないとき。

説明

ox_fuelは、車両の燃料残量をStateBags(Tier5-03参照)で管理し、給油時の支払い処理をsetPaymentMethodというexportで差し替えられる設計になっています。これにより、ESX/QBCore/独自フレームワークのどれを使っていても、支払い部分だけを自分の環境に合わせて実装できます。

コード例

server.lua: 支払い方法をカスタマイズする(ESXの例)

exports.ox_fuel:setPaymentMethod(function(playerId, amount)
    local xPlayer = ESX.GetPlayerFromId(playerId)
    local bankAmount = xPlayer.getAccount('bank').money

    if bankAmount >= amount then
        xPlayer.removeAccountMoney('bank', amount)
        return true -- 支払い成功
    end

    return false -- 支払い失敗(所持金不足)
end)

QBCoreの場合の例

exports.ox_fuel:setPaymentMethod(function(playerId, amount)
    local Player = QBCore.Functions.GetPlayer(playerId)
    if Player.PlayerData.money['bank'] >= amount then
        Player.Functions.RemoveMoney('bank', amount)
        return true
    end
    return false
end)

現在の燃料残量を取得する(StateBag経由)

local fuel = Entity(vehicleNetId).state.fuel
print(('燃料残量: %.1f%%'):format(fuel))

注意点・よくあるミス

  • setPaymentMethodに渡す関数は、必ずtrue(成功)かfalse/nil(失敗)を返してください。戻り値がないと、ox_fuel側が支払いの成否を正しく判定できません。
  • 燃料残量はStateBag(Entity(vehicle).state.fuel)として管理されているため、Tier5-03で学んだ「clientから直接書き換えず、正規の仕組みを通す」という原則がここでも当てはまります。
  • ox_fuelはox_inventoryとの併用を前提に設計されています。導入しているインベントリシステムがox_inventoryでない場合、ジェリー缶(携行缶)などのアイテム連携部分は別途調整が必要になることがあります。

補足

本レッスンの構文(setPaymentMethod、StateBagでの燃料取得)はOverextended公式ドキュメント(overextended.dev/ox_fuel)で確認済みです。setMoneyCheck(所持金チェック方法自体のカスタマイズ)等、他のexportもあるため、詳細は公式ドキュメントを確認してください。
