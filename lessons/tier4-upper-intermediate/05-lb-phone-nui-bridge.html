lb-phoneアプリのUIとLua間通信

結論

このレッスンを終えると、lb-phoneのカスタムアプリ画面に対して、通常のNUIとは異なる専用の仕組みでデータを送受信することができるようになります。

説明

Tier3で学んだ通常のNUIではSendNUIMessageを使いましたが、lb-phoneのアプリ画面(iframeとして電話UIの中に埋め込まれている)へは、代わりにSendCustomAppMessageという専用exportを使います。JS側での受け取り方自体は通常のNUIコールバックと同じwindow.addEventListener('message', ...)で書けます。

コード例

Lua側: アプリUIへメッセージを送信する

-- lb-phoneのアプリUIには SendNUIMessage ではなく、専用のエクスポートを使う
exports['lb-phone']:SendCustomAppMessage('my_custom_app', {
    action = 'updateData',
    payload = { balance = 1500 }
})

JS側: メッセージを受け取る(通常のNUIコールバックと同じ書き方)

window.addEventListener('message', (event) => {
  if (event.data.action === 'updateData') {
    // event.data.payload を使って画面を更新する
    document.getElementById('balance').textContent = event.data.payload.balance;
  }
});

アプリが開かれたタイミングの扱い方

// ❌ 悪い例: onOpen直後にUIがまだ読み込み中の可能性がある
// (lb-phone側のイベント名は導入バージョンのドキュメントを参照してください)

// ✅ 良い例: UI側から「準備完了」をLuaに伝えてもらってから、Lua側がデータを送る
document.addEventListener('DOMContentLoaded', () => {
  fetch(`https://${GetParentResourceName()}/appReady`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json; charset=UTF-8' },
    body: JSON.stringify({})
  });
});
RegisterNUICallback('appReady', function(data, cb)
    -- UI側の準備が整ったと分かった後で初めてデータを送る
    exports['lb-phone']:SendCustomAppMessage('my_custom_app', {
        action = 'updateData',
        payload = { balance = 1500 }
    })
    cb('ok')
end)

注意点・よくあるミス

  • onOpenコールバックのタイミングでは、UI(iframe)がまだ読み込み中の場合があります。onOpenから直接初期データを送らないでください。UI側から「準備完了」を伝えるコールバックを送ってもらい、それを受けてからLua側がデータを送る設計にします(上記コード例参照)。
  • 通常のNUIのSendNUIMessageとlb-phoneアプリのSendCustomAppMessageを混同しないでください。lb-phoneアプリに対してSendNUIMessageを呼んでも、アプリ画面には届きません。
  • SendCustomAppMessageの第1引数(アプリ識別子)は、前レッスンのConfig.CustomAppsのキーと完全に一致させる必要があります。

補足

※このレッスンで扱った構文(SendCustomAppMessage、Config.CustomApps、AddCustomApp/RemoveCustomApp)は実際のlb-phoneドキュメントで確認済みのものですが、バージョンによって仕様が変わる場合があります。公式ドキュメントも必ず確認してください。
