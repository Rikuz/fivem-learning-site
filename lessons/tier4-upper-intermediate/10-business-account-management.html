ビジネス/組織口座の管理

結論

このレッスンを終えると、個人ではなく「組織(会社・ギャング・警察署など)」に紐付いた口座を作り、その資金を管理することができるようになります。

こんな時に使う: Tier3-26のショップの売上を組織の資金として貯めたい、給料(Tier4-02)を組織の口座から支払いたい、複数人で共有する資金を管理したいとき。

説明

Tier4-06で学んだokokBankingV2のsocietyという概念は、まさにこの「組織口座」を指しています。個人の口座がプレイヤーのcitizenidを識別子にするのに対し、組織口座はjob名(またはギャング名)を識別子として使います。

コード例

server.lua: 組織の残高を確認する

local function getSocietyBalance(jobName)
    local account = exports['okokBanking']:GetAccount(jobName)
    return account and account.balance or 0
end

RegisterCommand('societybalance', function(source)
    -- Tier4-01のフレームワーク連携で、プレイヤーの所属Jobを取得する想定
    local jobName = getPlayerJob(source) -- 例: QBCoreならPlayer.PlayerData.job.name

    local balance = getSocietyBalance(jobName)
    TriggerClientEvent('myscript:notify', source, ('組織の残高: $%s'):format(balance))
end, false)

server.lua: ショップの売上を組織口座に入金する

local function depositToSociety(jobName, amount, reason)
    exports['okokBanking']:AddMoney(jobName, amount)
    exports['okokBanking']:AddTransaction(jobName, {
        value = amount,
        type = 'deposit',
        reason = reason,
    })
end

-- Tier3-26のショップ購入処理の中で呼び出す例
depositToSociety('mechanic', 500, '整備サービスの売上')

server.lua: 組織資金からの給料支払い(Tier4-02の応用)

local function paySalaryFromSociety(jobName, playerId, amount)
    local balance = getSocietyBalance(jobName)

    if balance < amount then
        return false -- 組織の資金が足りず支払えない
    end

    exports['okokBanking']:RemoveMoney(jobName, amount)
    -- 個人口座への入金はTier4-06参照
    exports['okokBanking']:AddMoney(getPlayerCitizenId(playerId), amount)
    return true
end

注意点・よくあるミス

  • 組織口座への入出金権限を誰にでも与えると、資金を勝手に引き出されてしまいます。Tier4-02のJob確認(特に階級・grade)と組み合わせ、経営者権限を持つプレイヤーだけが引き出せるようにするなどの制限が必要です。
  • 組織資金がマイナスにならないよう、給料支払い等の出金処理では必ず事前に残高を確認してください(Tier3-05のサーバー側バリデーションと同じ考え方)。
  • 複数の組織が同時に取引を行う可能性がある場合、Tier5-02の非同期処理の考え方(残高確認と減算の間に別の処理が割り込む「競合状態」)にも注意が必要です。

補足

okokBankingV2以外にも、Tier4-19で扱うRenewed-BankingのCreateJobAccountのように、組織口座の作成を専用exportで行える銀行スクリプトもあります。導入しているスクリプトのドキュメントを確認してください。
