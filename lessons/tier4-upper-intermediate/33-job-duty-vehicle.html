オンデューティ管理とジョブ専用車両の貸出

結論

このレッスンを終えると、「勤務中(オンデューティ)」かどうかをserverで管理し、勤務中のみジョブ専用車両を貸し出して勤務終了時に自動回収する仕組みを作れるようになります。Tier4-32のジョブループと組み合わせることで、より実際のジョブスクリプトに近い完成度になります。

こんな時に使う: Tier4-32で作ったデリバリージョブに、「出勤中しか仕事を受けられない」「専用車両は勤務中しか使えない」という制約を追加したいとき。

説明

オンデューティ管理は、プレイヤーごとに「勤務中かどうか」のフラグをserverで持つだけのシンプルな仕組みです。重要なのは、ジョブに関わる処理(仕事の受注・専用車両のスポーン)を全て「勤務中である」ことのチェックから始めるという設計上の徹底です。専用車両は、勤務終了時や切断時に必ず削除することで、車両が街に放置されるのを防ぎます。

コード例

server.lua: オンデューティの切り替え

local onDutyPlayers = {} -- playerId -> true

RegisterNetEvent('deliveryjob:toggleDuty')
AddEventHandler('deliveryjob:toggleDuty', function()
    local playerId = source
    local isNowOnDuty = not onDutyPlayers[playerId]

    onDutyPlayers[playerId] = isNowOnDuty or nil
    TriggerClientEvent('deliveryjob:onDutyChanged', playerId, isNowOnDuty)
end)

local function isOnDuty(playerId)
    return onDutyPlayers[playerId] == true
end

server.lua: 勤務中かどうかをジョブ受注のチェックに組み込む

RegisterNetEvent('deliveryjob:accept')
AddEventHandler('deliveryjob:accept', function()
    local playerId = source

    if not isOnDuty(playerId) then
        TriggerClientEvent('myscript:notify', playerId, '出勤してから仕事を受けてください', 'error')
        return
    end

    -- Tier4-32のジョブループ処理へ続く
end)

client.lua: 勤務開始時に専用車両をスポーンし、勤務終了時に回収する

local jobVehicle = nil

RegisterNetEvent('deliveryjob:onDutyChanged')
AddEventHandler('deliveryjob:onDutyChanged', function(isOnDuty)
    if isOnDuty then
        local model = `speedo` -- Tier1-11のハッシュ文字列(コンパイル時定数のためbacktick表記が使える)
        RequestModel(model)
        while not HasModelLoaded(model) do Wait(0) end

        local coords = vec3(-45.0, -1000.0, 26.0) -- 配送拠点の座標
        jobVehicle = CreateVehicle(model, coords.x, coords.y, coords.z, 0.0, true, false)
        SetVehicleOnGroundProperly(jobVehicle)
        SetModelAsNoLongerNeeded(model)

        TriggerEvent('myscript:notify', '配送車両が貸し出されました', 'success')
    else
        if jobVehicle and DoesEntityExist(jobVehicle) then
            SetEntityAsMissionEntity(jobVehicle, true, true)
            DeleteEntity(jobVehicle)
            jobVehicle = nil
        end
        TriggerEvent('myscript:notify', 'お疲れさまでした。車両を返却しました', 'success')
    end
end)

-- 切断時にも確実に車両を削除する(Tier2-15の切断イベントの応用)
AddEventHandler('onResourceStop', function(resourceName)
    if GetCurrentResourceName() ~= resourceName then return end
    if jobVehicle and DoesEntityExist(jobVehicle) then
        DeleteEntity(jobVehicle)
    end
end)

注意点・よくあるミス

  • 「勤務中かどうか」の最終判定は必ずserver側のonDutyPlayersを使ってください。client側の変数だけで判定すると、改造クライアントで勤務外でも仕事を受注できてしまいます。
  • 専用車両はプレイヤーごとに1台までに制限してください(既にスポーン済みなら再スポーンしない、または既存の車両を削除してから新しく出す)。制限しないと勤務のたびに車両が増え続けます。
  • プレイヤーが車両に乗ったまま切断した場合の扱い(車両を残す/削除する)も、サーバーの運用方針として事前に決めておきましょう。

補足

実際のRPフレームワーク(ESX/QBCore/Qbox)には、Job自体にJobごとの車両情報を持たせる仕組みが用意されていることも多いです。導入しているフレームワークにその機能がある場合は、自作の車両貸出処理をそちらに寄せることも検討してください(Tier4-01参照)。
