自宅の収納・施錠システム(ox_inventory + ox_doorlockとの連携)

結論

このレッスンを終えると、自宅の玄関をox_doorlockで施錠し、所有者専用の収納(スタッシュ)をox_inventoryで用意することができるようになります。Tier4-34で作った所有権テーブルと、Tier3-37・Tier4-14で学んだ既存の仕組みを組み合わせるだけで実装できます。

こんな時に使う: Tier4-34で購入できるようになった物件に、「他人は入れない」「収納にアイテムを保管できる」という住居らしい機能を追加したいとき。

説明

住居の収納・施錠は、Tier3-37のRegisterStashとTier4-14のox_doorlockを「所有権テーブルと連動させる」だけで実現できます。ポイントは、スタッシュのid・ドアのidを物件idから一意に導出することです(例: house_stash_ + propertyId)。こうすることで、物件が増えてもコードを複製せずに済みます。

コード例

server.lua: 物件ごとの収納をまとめて登録する

CreateThread(function()
    local properties = MySQL.query.await('SELECT id FROM properties', {})

    for _, property in ipairs(properties or {}) do
        -- RegisterStash(id, label, slots, weight, owner, groups) — Tier3-37参照
        -- owner/groupsは指定せず、「誰でも開けるが実際のアクセス制御はox_target側で行う」設計にする
        exports.ox_inventory:RegisterStash('house_stash_' .. property.id, '自宅の収納', 40, 80000)
    end
end)

client.lua: 玄関にox_targetで施錠・入室インタラクションを追加する

local function addPropertyDoorTarget(propertyId, coords)
    exports.ox_target:addBoxZone({
        coords = coords,
        size = vec3(1.5, 1.5, 2.5),
        options = {
            {
                name = 'enter_property_' .. propertyId,
                icon = 'fa-solid fa-door-open',
                label = '中に入る',
                onSelect = function()
                    TriggerServerEvent('housing:requestEnter', propertyId)
                end,
            },
            {
                name = 'open_property_stash_' .. propertyId,
                icon = 'fa-solid fa-box',
                label = '収納を開ける',
                onSelect = function()
                    TriggerServerEvent('housing:requestOpenStash', propertyId)
                end,
            },
        }
    })
end

server.lua: 所有者本人であることを確認してから入室・収納アクセスを許可する

local function isOwner(playerId, propertyId)
    local identifier = GetPlayerIdentifierByType(playerId, 'license')
    local owner = MySQL.scalar.await('SELECT owner_identifier FROM property_owners WHERE property_id = ?', { propertyId })
    return owner == identifier
end

RegisterNetEvent('housing:requestEnter')
AddEventHandler('housing:requestEnter', function(propertyId)
    local playerId = source

    if not isOwner(playerId, propertyId) then
        TriggerClientEvent('myscript:notify', playerId, 'この物件の所有者ではありません', 'error')
        return
    end

    local furniture = MySQL.query.await('SELECT model, x, y, z, heading FROM property_furniture WHERE property_id = ?', { propertyId })
    TriggerClientEvent('housing:loadFurniture', playerId, furniture or {}) -- Tier4-35参照
end)

RegisterNetEvent('housing:requestOpenStash')
AddEventHandler('housing:requestOpenStash', function(propertyId)
    local playerId = source

    if not isOwner(playerId, propertyId) then
        TriggerClientEvent('myscript:notify', playerId, 'この物件の所有者ではありません', 'error')
        return
    end

    TriggerClientEvent('housing:openStash', playerId, 'house_stash_' .. propertyId)
end)

注意点・よくあるミス

  • ox_inventoryのRegisterStash自体には所有者を絞るowner引数がありますが、物件ごとに動的に変わる所有者(購入・転売で変化する)を都度RegisterStashし直すのは非効率です。上記コード例のように、アクセス制御はox_target側のonSelect→server側の所有権確認で行う設計の方が扱いやすくなります。
  • 入室・収納アクセスの権限チェックは必ずserver側のhousing:requestEnter/housing:requestOpenStashハンドラで行ってください。client側のonSelectだけで判定すると、直接イベントを発火されて回避されます(これまでの管理者メニュー等と同じ注意点)。
  • 物件を転売(Tier4-34)した場合、旧所有者が収納の中身を持ち逃げできないよう、売却時に収納を空にする、または中身ごと引き継がれる仕様にするかを事前に決めておきましょう。

補足

複数物件を所有できる設計にする場合、プレイヤーが物件一覧から入りたい家を選べるUI(ox_libのコンテキストメニュー、Tier3-35参照)を用意すると使い勝手が向上します。これで住居システムの主要機能(購入・家具設置・収納・施錠)が揃いました。演習ex-13ではこれらを1つのresourceとして統合します。
