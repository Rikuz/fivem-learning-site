Discord連携(OAuth・ロール確認)

結論

このレッスンを終えると、プレイヤーのDiscordアカウントを識別し、サーバーのDiscordで持っているロール(役職)に応じて機能を制限する連携の考え方を理解できるようになります。

こんな時に使う: Discordで「メンバー」ロールを持つ人だけ参加を許可したい、Discordブースター特典をゲーム内に反映したいとき。

説明

FiveMのプレイヤーには、Tier2-15でも触れたGetPlayerIdentifiersで取得できる識別子の1つとしてdiscord:から始まるDiscordユーザーIDが含まれます(プレイヤーがFiveMクライアントでDiscordと連携している場合)。このIDと、Discord Bot側のAPI(Botのトークンを使ってサーバーメンバーのロール情報を取得するAPI)を組み合わせることで、ロールに応じた判定ができます。

コード例

server.lua: プレイヤーのDiscord IDを取得する

local function getDiscordId(playerId)
    for _, id in ipairs(GetPlayerIdentifiers(playerId)) do
        if id:find('discord:') then
            return id:gsub('discord:', '')
        end
    end
    return nil
end

server.lua: Discord APIにロール情報を問い合わせる(概念)

local DISCORD_BOT_TOKEN = 'あなたのBotトークン' -- Tier3-22同様、Config等に分離し秘匿すること
local DISCORD_GUILD_ID = 'あなたのサーバーID'
local REQUIRED_ROLE_ID = '必要なロールのID'

local function checkPlayerHasRole(discordId, callback)
    PerformHttpRequest(
        ('https://discord.com/api/guilds/%s/members/%s'):format(DISCORD_GUILD_ID, discordId),
        function(statusCode, responseText)
            if statusCode ~= 200 then
                callback(false)
                return
            end

            local member = json.decode(responseText)
            local hasRole = false
            for _, roleId in ipairs(member.roles or {}) do
                if roleId == REQUIRED_ROLE_ID then hasRole = true end
            end
            callback(hasRole)
        end,
        'GET',
        '',
        { ['Authorization'] = 'Bot ' .. DISCORD_BOT_TOKEN }
    )
end

playerConnectingと組み合わせる(Tier4-07参照)

AddEventHandler('playerConnecting', function(playerName, setKickReason, deferrals)
    deferrals.defer()
    Wait(0)

    local source = source
    local discordId = getDiscordId(source)

    if not discordId then
        deferrals.done('Discordと連携したFiveMアカウントで参加してください')
        return
    end

    checkPlayerHasRole(discordId, function(hasRole)
        if hasRole then
            deferrals.done()
        else
            deferrals.done('Discordサーバーで必要なロールを取得してから参加してください')
        end
    end)
end)

注意点・よくあるミス

  • Discord BotのトークンはWebhook URL以上に機密性が高い情報です。絶対にコードに直書きしたままコミットしないでください。漏洩するとBotを乗っ取られる危険があります。
  • Discord APIには利用回数の制限(レート制限)があります。全プレイヤーの接続のたびに毎回問い合わせると、制限に達してエラーになることがあります。実運用ではキャッシュ(Tier3-16参照)と組み合わせることも検討してください。
  • プレイヤーがDiscordとFiveMを連携していない場合、discord:識別子自体が存在しません。この場合の扱い(拒否するか、機能を制限した上で許可するか)をあらかじめ決めておきましょう。

補足

Discord APIの詳細な仕様(エンドポイント・レート制限・認証方式)は変更されることがあるため、実装時はDiscordの公式APIドキュメント(discord.com/developers/docs)を必ず確認してください。本レッスンは連携の考え方の紹介にとどめています。
