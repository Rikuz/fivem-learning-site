BAN・キック機能を実装する

結論

このレッスンを終えると、プレイヤーを即座にキックする機能と、接続時にBANリストをチェックして参加自体を拒否する機能を実装できるようになります。

説明

「今すぐ切断させる」キックにはDropPlayerを使います。一方「そもそもサーバーに参加させない」BANは、プレイヤーが接続してくる際に発生するplayerConnectingイベントの中で、deferrals(接続処理を保留し、DB確認などの非同期処理を待ってから許可/拒否を決める仕組み)を使って判定します。

コード例

即座にキックする

RegisterCommand('kick', function(source, args)
    if not IsPlayerAceAllowed(source, 'command.kick') then return end

    local targetId = tonumber(args[1])
    local reason = table.concat(args, ' ', 2) or '理由未記載'

    if targetId then
        DropPlayer(targetId, ('管理者によってキックされました: %s'):format(reason))
    end
end, false)

接続時にBANリストをチェックする

local bannedIdentifiers = {
    ['license:1234567890abcdef1234567890abcdef12345678'] = '規約違反のため',
}

AddEventHandler('playerConnecting', function(playerName, setKickReason, deferrals)
    deferrals.defer() -- 接続処理を保留し、非同期チェックの時間を確保する

    -- 1フレーム待つのは公式に推奨されている作法(deferralsの初期化を待つため)
    Wait(0)

    local source = source
    local identifiers = GetPlayerIdentifiers(source)

    for _, identifier in ipairs(identifiers) do
        if bannedIdentifiers[identifier] then
            deferrals.done(('接続が拒否されました: %s'):format(bannedIdentifiers[identifier]))
            return
        end
    end

    deferrals.done() -- 引数なしで呼ぶと接続を許可する
end)

DBを使ったBANチェック(oxmysql, Tier3-03参照)

AddEventHandler('playerConnecting', function(playerName, setKickReason, deferrals)
    deferrals.defer()
    Wait(0)

    local source = source
    local identifiers = GetPlayerIdentifiers(source)
    local license = nil
    for _, id in ipairs(identifiers) do
        if id:find('license:') then license = id end
    end

    MySQL.Async.fetchAll('SELECT reason FROM bans WHERE identifier = @id', { ['@id'] = license }, function(result)
        if result and result[1] then
            deferrals.done(('接続が拒否されました: %s'):format(result[1].reason))
        else
            deferrals.done()
        end
    end)
end)

注意点・よくあるミス

  • deferrals.done()を必ずどこかの分岐で呼んでください。呼ばずに関数を抜けると、そのプレイヤーはいつまでも接続処理中のまま止まってしまいます。
  • deferrals.defer()を呼ばずに非同期処理(DBアクセス等)を待とうとすると正しく動作しません。非同期にBANチェックしたい場合は必ず先にdeferrals.defer()を呼んでください。
  • 識別子(identifier)にはlicense:、steam:、discord:など複数の種類があります。どれか1種類だけでBAN判定すると、別の識別子で再接続されて回避されることがあります。運用ではIPアドレスやハードウェアID(利用可能な場合)も含め、複数の識別子で判定することが多いです。

補足

本格的な運用では、BAN理由・期間・執行者などを記録するテーブル設計や、管理者用のNUI画面と組み合わせることが多いです。ここで学んだplayerConnecting + deferralsの仕組みは、その土台になる部分です。
