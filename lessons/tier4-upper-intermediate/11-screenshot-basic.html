screenshot-basicでスクリーンショットを取得する

結論

このレッスンを終えると、screenshot-basic(FiveM公式が提供するスクリーンショット取得用リソース)を使い、プレイヤーの画面を証拠として保存することができるようになります。

こんな時に使う: 通報(Tier3-21)を受けた際の証拠として画面を残したい、身分証明書のような画像をゲーム内で生成したいとき。

説明

screenshot-basicは、server側から特定プレイヤーの画面のスクリーンショットを要求できるリソースです。取得した画像は、サーバー上のファイルとして保存するか、data URI(画像データを文字列として表現したもの)としてコールバックで受け取るかを選べます。

コード例

server.lua: 特定プレイヤーのスクリーンショットを取得する

exports['screenshot-basic']:requestClientScreenshot(GetPlayers()[1], {
    fileName = 'cache/screenshot.jpg'
}, function(err, data)
    print('err', err)
    print('data', data)
end)

通報システム(Tier3-21)と組み合わせる例

RegisterCommand('reportscreenshot', function(source, args)
    if not IsPlayerAceAllowed(source, 'command.adminmenu') then return end

    local targetId = tonumber(args[1])
    if not targetId then return end

    exports['screenshot-basic']:requestClientScreenshot(targetId, {
        encoding = 'jpg',
        quality = 0.8
    }, function(err, data)
        if err then
            print('スクリーンショットの取得に失敗しました: ' .. tostring(err))
            return
        end

        -- dataにはdata URI文字列が入る。Discord Webhook(Tier3-22)に添付する等の活用ができる
        print('スクリーンショットを取得しました')
    end)
end, false)

注意点・よくあるミス

  • この機能を使うには、少なくともある程度新しいバージョンのFiveMクライアント・サーバーが必要です(古いバージョンでは動作しません)。動作しない場合はまずアップデートを確認してください。
  • プレイヤーの同意なくスクリーンショットを取得する機能は、プライバシーに関わります。通報対応など、正当な理由がある場合に限定して使い、利用規約等でその旨を明記しておくことが望まれます。
  • fileNameを指定した場合、画像はサーバーのファイルシステムに保存されます。保存先の容量管理(古い画像の自動削除等)も運用上考慮してください。

補足

取得したスクリーンショットをTier3-22のDiscord Webhookで管理者チャンネルに自動送信する運用もよく見られます。ただしdata URIをそのままWebhookのJSONに含めるのは適さないため、実際にはmultipart形式でのファイルアップロードなど別の送信方法を検討する必要があります。
