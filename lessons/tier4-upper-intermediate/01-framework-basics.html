ESX/QBCore/Qbox/oxの基本

結論

このレッスンを終えると、ESX・QBCore・Qbox・ox_coreという主要なRPフレームワークからプレイヤーオブジェクトを取得し、お金や職業などの基本データを読み取ることができるようになります。

説明

フレームワーク(RPサーバーの土台となる基盤スクリプト。プレイヤーデータ・お金・職業などの管理を共通化してくれる)にはいくつかの系統があります。

  • ESX(es_extended) — 古くから使われている定番フレームワーク。
  • QBCore(qb-core) — ESXと並んで人気のフレームワーク。テーブル構造が異なる。
  • Qbox(qbx_core) — QBCoreのメンテナンス終了後に登場した後継的な位置づけのフレームワーク。QBCoreとのAPI互換性を保つ設計方針を掲げており、既存のQBCore向けスクリプトの多くがそのまま動くよう作られている。
  • ox_core — Overextended(oxシリーズ)によるフレームワーク。ESX/QBCoreとは異なる、クラスベースの設計を採用している。

自作スクリプトを複数のフレームワークに対応させたい場合、「どのフレームワークが導入されているか検知し、それぞれの流儀でプレイヤーデータを取得する」という分岐処理を書くのが基本パターンです。

コード例

ESX(es_extended)

local ESX = exports['es_extended']:getSharedObject()

RegisterNetEvent('myscript:checkMoney')
AddEventHandler('myscript:checkMoney', function()
    local xPlayer = ESX.GetPlayerFromId(source)
    local money = xPlayer.getMoney()
    local jobName = xPlayer.job.name

    print(('ESX: money=%s job=%s'):format(money, jobName))
end)

QBCore(qb-core)

local QBCore = exports['qb-core']:GetCoreObject()

RegisterNetEvent('myscript:checkMoney')
AddEventHandler('myscript:checkMoney', function()
    local Player = QBCore.Functions.GetPlayer(source)
    local cash = Player.PlayerData.money['cash']
    local jobName = Player.PlayerData.job.name

    print(('QBCore: cash=%s job=%s'):format(cash, jobName))
end)

Qbox(qbx_core)

-- Qboxは移行のしやすさを重視しており、QBCoreと同じ 'qb-core' 互換exportが使える
local QBCore = exports['qb-core']:GetCoreObject()

RegisterNetEvent('myscript:checkMoney')
AddEventHandler('myscript:checkMoney', function()
    -- 以降はQBCoreと同じ書き方でPlayerData.money / PlayerData.jobにアクセスできる想定
    local Player = QBCore.Functions.GetPlayer(source)
    print(('Qbox: job=%s'):format(Player.PlayerData.job.name))
end)

ox_core

RegisterNetEvent('myscript:checkMoney')
AddEventHandler('myscript:checkMoney', function()
    local player = exports.ox_core:GetPlayer(source)
    if player then
        -- ox_coreはクラスベースのアクセサ(get/set等)でデータを扱う設計
        print(('ox_core: player取得に成功'))
    end
end)

フレームワークを検知して分岐する例

local function detectFramework()
    if GetResourceState('es_extended') == 'started' then
        return 'esx'
    elseif GetResourceState('qbx_core') == 'started' then
        return 'qbox'
    elseif GetResourceState('qb-core') == 'started' then
        return 'qbcore'
    elseif GetResourceState('ox_core') == 'started' then
        return 'ox'
    end
    return nil
end

local framework = detectFramework()
print('検知したフレームワーク: ' .. tostring(framework))

注意点・よくあるミス

  • GetResourceStateで存在確認する際は、qbx_core(Qbox)をqb-core(QBCore本家)より先にチェックしてください。QboxはQBCore互換のqb-coreexportブリッジも同時に提供する場合があり、順序を間違えると誤検知することがあります。
  • ESXはgetMoney()のように現金のみを返す関数と、xPlayer.getAccount('bank').moneyのように口座ごとに分かれた関数が混在します。QBCoreもPlayerData.money['cash']/['bank']のように複数の財布があります。「お金」と一括りにせず、どの財布を指すか意識してください。
  • ox_coreはESX/QBCoreとテーブル構造が根本的に異なります。「QBCore用に書いたコードをox_core向けに少し直せば動く」という考え方は通用しません。

補足

⚠️ Qbox(qbx_core)がQBCore互換の'qb-core'exportを提供する点は公式の設計方針として広く知られていますが、qbx_core独自exportやox_coreのメソッド名(get/getGroup等)は、本レッスン作成時点で公式ドキュメントの一字一句までは確認できていません。実際に導入するバージョンのドキュメント(Qbox: docs.qbox.re、ox_core: Overextended/CommunityOxのドキュメント)を必ず確認してから実装してください。okokシリーズ・lb-phoneの構文(Tier4後半で扱います)とは異なり、このレッスンのQbox/ox_core部分は「概ねこういう設計思想」という紹介にとどまります。
