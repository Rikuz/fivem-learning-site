illenium-appearanceでキャラクリエイトする

結論

このレッスンを終えると、illenium-appearance(ESX/QBCore向けの人気キャラクリエイトスクリプト)でキャラクター作成・見た目編集画面を開き、結果を受け取ってDBに保存することができるようになります。

こんな時に使う: Tier2-13のペド見た目変更を1から自作せず、洗練されたキャラクリエイト画面を導入したいとき。

説明

illenium-appearanceは、Tier2-10で学んだカメラ演出とTier2-13の服装変更を内部で組み合わせ、プレイヤーが自分でスライダーやボタンを操作して見た目を編集できるUIを提供してくれるリソースです。呼び出す側はstartPlayerCustomizationというexportを呼ぶだけで、複雑なカメラ制御・UI表示を自分で作る必要がありません。

コード例

client.lua: キャラクリエイト画面を開く

local function openCharacterCreator()
    exports['illenium-appearance']:startPlayerCustomization(function(appearance)
        if appearance then
            -- プレイヤーが「確定」した場合、appearanceに見た目データが入る
            TriggerServerEvent('myscript:saveAppearance', appearance)
        else
            -- 「キャンセル」した場合はnilが渡ってくる
            print('キャラクリエイトがキャンセルされました')
        end
    end)
end

RegisterCommand('customize', openCharacterCreator, false)

server.lua: 見た目データをDBに保存する

RegisterNetEvent('myscript:saveAppearance')
AddEventHandler('myscript:saveAppearance', function(appearance)
    local source = source
    local identifier = GetPlayerIdentifiers(source)[1]

    MySQL.Async.execute('UPDATE users SET appearance = @appearance WHERE identifier = @id', {
        ['@appearance'] = json.encode(appearance), -- Tier3-17参照: 見た目データはJSON列で保存するのが一般的
        ['@id'] = identifier
    })
end)

注意点・よくあるミス

  • startPlayerCustomizationのコールバックは、確定時とキャンセル時の両方で呼ばれます。appearanceがnilかどうかを必ず確認してから保存処理を行ってください。
  • 初回キャラクター作成時と、後から見た目を変更する場合(美容院など)とでは、illenium-appearance側に用意されている設定(第2引数のconfテーブル)が異なることがあります。用途に応じたオプションを確認してください。
  • 見た目データの保存先(appearance列)は、Tier3-17で学んだJSON保存が適しています。個別の項目(髪型・肌の色など)ごとにテーブルを分けると管理が煩雑になりがちです。

補足

本レッスンのstartPlayerCustomizationのexport構文は、公式GitHubリポジトリ(github.com/iLLeniumStudios/illenium-appearance)のソースコードで確認済みです。保存済みデータの再適用方法など、細部の仕様は導入しているバージョンのドキュメント(docs.illenium.dev)を確認してください。
