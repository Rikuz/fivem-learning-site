スレッドとループ

結論

このレッスンを終えると、CreateThreadで繰り返し処理を作り、Wait()を絶対に省略してはいけない理由を理解し、安全なループが書けるようになります。

説明

CreateThread(function() ... end)は、渡した関数を新しい処理の流れ(スレッド)として実行します。ループ処理(ミニマップ表示の更新、近くのプレイヤー確認など)は、この中にwhile true do ... endを書いて実現するのが基本パターンです。

FiveMのLuaスレッドは協調的スケジューリング(1つの処理が自分から「一旦ここで他の処理に順番を譲ります」と言わない限り、他の処理が実行されない仕組み)で動いています。その「順番を譲る」合図がWait(ミリ秒)です。

コード例

基本的なループ

CreateThread(function()
    while true do
        Wait(1000) -- 1秒待つ。この行がループの中に必須

        local playerCount = #GetActivePlayers()
        print('現在の接続人数: ' .. playerCount)
    end
end)

絶対にやってはいけない書き方

-- ⚠️ これは書いてはいけない例です(解説のために掲載しています)
CreateThread(function()
    while true do
        -- Wait()がない!
        local playerCount = #GetActivePlayers()
    end
end)

このWait()抜きのループは、他の処理に一切順番を譲らないまま無限に回り続けます。FiveMは1フレームの中でこのスレッドの処理が終わるのを待ち続けてしまうため、そのリソースだけでなくサーバー全体がフリーズ・激重化する危険があります。

負荷を抑えた書き方の例

CreateThread(function()
    while true do
        local playerCoords = GetEntityCoords(PlayerPedId())
        local nearShop = #(playerCoords - vector3(100.0, 200.0, 30.0)) < 20.0

        if nearShop then
            -- 近くにいる間だけ細かく処理する(Marker描画など)
            Wait(0)
        else
            -- 遠くにいる間はチェック頻度を大きく下げる
            Wait(1000)
        end
    end
end)

注意点・よくあるミス

  • Wait(0)は「待ち時間0ミリ秒」という意味ですが、これは「待たない」のではなく「次のフレームまで待つ」という意味です。Wait()自体を省略するのとは全く違います。
  • if文の中だけにWait()を置き、条件を満たさない場合にWait()を通らない書き方をすると、条件によっては無限ループになってしまいます。全ての分岐で必ずWait()を通るように書いてください。
  • 常にWait(0)(毎フレーム)で細かい処理を回し続けると、それだけでクライアントの負荷が上がります。本当に毎フレーム必要な処理か、上記コード例のように距離などで頻度を切り替えられないか検討しましょう(詳しくはTier5「パフォーマンス計測と最適化」)。
