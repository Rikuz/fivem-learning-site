プレイヤー識別子(GetPlayerIdentifiers)の使い分け

結論

このレッスンを終えると、プレイヤーを一意に識別するための複数の識別子(license/steam/discord等)の違いを理解し、DBの主キーにどれを使うべきか判断できるようになります。これまでのレッスン(Tier3のDB連携やTier4のBAN機能など)で何度もGetPlayerIdentifiersを使ってきましたが、その中身をきちんと扱うのはこのレッスンが初めてです。

説明

1人のプレイヤーは、Steam・Discord・Rockstar Online Servicesなど複数のサービスに紐づいた複数の識別子を同時に持っています。GetPlayerIdentifiers(source)は、それら全てを配列として返します。どの識別子をDBの主キー(プレイヤーを一意に表す値)として使うかは、サーバー設計上の重要な判断になります。

コード例

全識別子を確認する

RegisterCommand('myidentifiers', function(source)
    local identifiers = GetPlayerIdentifiers(source)
    for _, id in ipairs(identifiers) do
        print(id)
    end
    -- 出力例:
    -- license:1234567890abcdef1234567890abcdef12345678
    -- license2:abcdef1234567890abcdef1234567890abcdef12
    -- steam:110000112345678
    -- discord:123456789012345678
    -- fivem:1234567
    -- ip:192.0.2.1
end, false)

特定の種類の識別子だけを取り出す

local function getIdentifierByPrefix(source, prefix)
    for _, id in ipairs(GetPlayerIdentifiers(source)) do
        if id:find(prefix .. ':') then
            return id
        end
    end
    return nil
end

local license = getIdentifierByPrefix(source, 'license')
local discordId = getIdentifierByPrefix(source, 'discord')

1つだけ取得したい場合の専用native

-- GetPlayerIdentifierByType(source, identifierType)
local steamId = GetPlayerIdentifierByType(source, 'steam')

注意点・よくあるミス

  • 主な識別子: license(Rockstar Online Servicesのハッシュ)、license2(Steam経由利用時のROSライセンス。licenseと同じ値になる場合がある)、steam、discord、fivem(Cfx.re User Id)、ip。全てのプレイヤーが全種類の識別子を持っているとは限りません(Steamを使わずEpic Games経由で接続している場合、steamは存在しない等)。
  • コミュニティの多くのスクリプト(ESX/QBCore含む)は歴史的経緯でlicenseを主キーとして使うことが多いですが、公式(Cfx)はセキュリティ上、fivem識別子を最も推奨し、次点でdiscordを推奨しています。新規に設計するなら、この点を踏まえて選択してください。
  • 導入しているフレームワーク(ESX/QBCore)が既に特定の識別子を主キーとして使っている場合、自作スクリプトだけ別の識別子を使うとデータが紐付かなくなります。フレームワークの慣例に合わせるのが安全です。
  • ip識別子は環境によって変動する(再接続で変わる)ことがあるため、永続的なプレイヤー識別には向きません。

補足

Tier4-07のBAN機能や、多くのDB連携レッスンでidentifiers[1]のように先頭の識別子をそのまま使ってきましたが、実際には配列内の順序は保証されていません。本番運用では、このレッスンのgetIdentifierByPrefixのように、目的の種類を明示的に探す実装にすることを推奨します。
