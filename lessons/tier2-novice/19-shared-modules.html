shared_scriptを使ったモジュール分割

結論

このレッスンを終えると、大きくなってきたresourceを、用途ごとの複数ファイルに分割して見通し良く管理することができるようになります。

こんな時に使う: 1つのclient.lua/server.luaが数百行を超えて読みにくくなってきたとき、複数人で同じresourceを分担して編集したいとき。

説明

Tier1-09で学んだConfig.luaの考え方をさらに発展させ、「共通の定数・ヘルパー関数」「client専用処理」「server専用処理」のようにファイルを分割します。shared_scriptで読み込んだファイルは、client側実行時はclient環境で、server側実行時はserver環境で、それぞれ独立して実行される点がポイントです(Tier1-04でも触れた内容の応用です)。

コード例

ディレクトリ構成の例

my-resource/
├── fxmanifest.lua
├── config.lua              -- 設定値(shared)
├── shared/
│   └── utils.lua            -- client/server共通のヘルパー関数(shared)
├── client/
│   ├── main.lua
│   └── ui.lua
└── server/
    ├── main.lua
    └── database.lua

fxmanifest.lua

shared_scripts {
    'config.lua',
    'shared/utils.lua'
}

client_scripts {
    'client/main.lua',
    'client/ui.lua'
}

server_scripts {
    'server/main.lua',
    'server/database.lua'
}

shared/utils.lua: 共通のヘルパー関数

-- client/serverどちらからも呼び出せる純粋な計算関数
function FormatMoney(amount)
    return '$' .. tostring(amount):reverse():gsub('(%d%d%d)', '%1,'):reverse():gsub('^,', '')
end

client/main.lua: 共通関数を使う

RegisterCommand('showmoney', function()
    print(FormatMoney(15000)) -- $15,000
end, false)

注意点・よくあるミス

  • shared_scripts内のファイルは「1回だけ実行されてclient/serverで共有される」わけではありません。client側とserver側でそれぞれ個別に読み込まれ、個別に実行されます(Tier1-04でも扱った注意点です)。グローバル変数の値をclient→serverのように直接渡すことはできません。
  • ファイル分割をやりすぎると、逆に「どの処理がどのファイルにあるか」が分かりにくくなります。まずは「client/server」「共通/固有」で分け、必要になったらさらに細分化する、という段階的な分割がおすすめです。
  • client_scripts/server_scripts内のファイルは書かれた順番に実行されます。後のファイルが前のファイルで定義した関数・変数に依存する場合は、順番を意識してください。

補足

この設計は、Tier3-06で学んだexports(resourceをまたぐ連携)と組み合わせることで、さらに大きなプロジェクト全体の構成(Tier3-09「複数resourceにまたがるプロジェクト構成のコツ」)にもつながっていきます。
