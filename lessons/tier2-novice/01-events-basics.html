🟡 初級 📡 イベント/通信

イベントの基礎(client↔server通信)

結論

このレッスンを終えると、クライアント(プレイヤーの画面)とサーバーの間でデータをやり取りする基本パターンが書けるようになります。これはFiveMスクリプトの最も基本的な仕組みです。

説明

FiveMのスクリプトはclient(各プレイヤーのPC上で動く部分)とserver(サーバー上で動く部分)に分かれています。お金の増減やデータベースの保存など「不正な改ざんを防ぎたい処理」は必ずserver側で行い、画面表示やキー入力の検知などは client側で行います。

この2つの間で情報をやり取りするのがイベントです。イベントには名前(文字列)を付け、TriggerServerEvent/TriggerClientEventで「発火」し、あらかじめRegisterNetEventで登録しておいた側がそれを受け取ります。

コード例

client.lua: サーバーにイベントを送る

-- Eキーを押したら、サーバーに「アイテムを拾いたい」と伝える
RegisterCommand('pickup', function()
    TriggerServerEvent('myscript:pickupItem', 'apple')
end, false)

RegisterKeyMapping('pickup', 'アイテムを拾う', 'keyboard', 'E')

server.lua: イベントを受け取り、結果を返す

RegisterNetEvent('myscript:pickupItem')
AddEventHandler('myscript:pickupItem', function(itemName)
    -- sourceはイベントを送ってきたプレイヤーのIDを表すグローバル変数(server側のみ)
    local playerId = source

    print(('プレイヤー%sが%sを拾おうとしました'):format(playerId, itemName))

    -- ここでDBに保存する等の処理を行う(Tier3で扱う)

    -- 結果をそのプレイヤーのclientに送り返す
    TriggerClientEvent('myscript:pickupResult', playerId, true, itemName)
end)

client.lua: サーバーからの結果を受け取る

RegisterNetEvent('myscript:pickupResult')
AddEventHandler('myscript:pickupResult', function(success, itemName)
    if success then
        print(itemName .. ' を拾いました!')
    end
end)

注意点・よくあるミス

  • RegisterNetEventを呼ばずにAddEventHandlerだけ書くと、他のresourceから送られてきたネットワークイベントを受け取れません(ローカル内で完結するイベントとしてしか動きません)。ネットワーク越しに送受信する場合は必ず両方セットで書きます。
  • server側のsourceは「そのイベントを直前にトリガーしたプレイヤーのID」を指す特別な変数です。非同期処理の中で使い回すと値がずれることがあるため、受け取った直後に別の変数へ代入しておくと安全です(上記コード例のlocal playerId = source)。
  • client→serverの通信は信用できません。「アイテムを拾えたことにする」処理を全てclient側だけで完結させると、チートで無限に増やされてしまいます。判定や保存は必ずserver側で行ってください(詳しくはTier3「サーバー側バリデーション」)。

補足

TriggerClientEventの第2引数にプレイヤーIDの代わりに-1を渡すと、接続している全プレイヤーに送信できます(全体通知などに利用)。
