ルーティングバケットでインスタンスを分ける

結論

このレッスンを終えると、プレイヤーやエンティティを別々の「見え方のグループ(バケット)」に分け、同じ座標にいても互いに見えない・干渉しない状態を作ることができるようになります。

こんな時に使う: 強盗ミッションを複数グループが同時に進められるようにしたい(お互いのグループが見えないようにする)、キャラクター選択画面中は他プレイヤーと干渉させたくないとき。

説明

ルーティングバケットは、サーバー上の全プレイヤー・エンティティに割り当てられる「グループ番号」のようなものです。デフォルトでは全員がバケット0に属しており、同じワールドを共有しています。異なるバケット番号を設定すると、そのプレイヤー(やエンティティ)は別のバケットに属するものを一切認識できなくなります(座標が同じでも、まるで別のインスタンスにいるかのように振る舞います)。

コード例

server.lua: プレイヤーを別のバケットに移動する

local function movePlayerToInstance(playerId, bucketId)
    SetPlayerRoutingBucket(playerId, bucketId)
end

-- 強盗グループを個別のインスタンスに入れる例
RegisterCommand('startheist', function(source)
    local heistGroupId = 100 + math.random(1, 999) -- グループごとに一意な番号を割り当てる

    movePlayerToInstance(source, heistGroupId)
    TriggerClientEvent('myscript:notify', source, '強盗インスタンスに移動しました')
end, false)

エンティティ(NPC・車両)を特定のバケットに紐付ける

local heistGuard = CreatePed(4, `s_m_y_swat_01`, 100.0, 200.0, 30.0, 0.0, true, false)
SetEntityRoutingBucket(heistGuard, heistGroupId) -- このNPCはheistGroupId のバケットにいるプレイヤーにしか見えない

元のワールド(バケット0)に戻す

RegisterCommand('endheist', function(source)
    SetPlayerRoutingBucket(source, 0)
end, false)

注意点・よくあるミス

  • プレイヤーをバケット移動した後、そのプレイヤーが生成したNPC・車両等も同じバケットに紐付ける必要があります。忘れると、プレイヤー本人は別インスタンスにいるのに、生成物だけが元のワールド(バケット0)に残ってしまいます。
  • バケット番号は「グローバルに全サーバーで共有される数値」です。複数の強盗グループを同時に走らせる場合、番号が重複しないよう管理する仕組み(上記コード例のようなランダム割り当てや、使用中バケットのリスト管理)が必要です。
  • チャット・イベント通知などの一部の仕組みは、デフォルトではバケットを考慮せず全員に送られます。バケットごとに独立させたい通知は、対象プレイヤーのバケットを確認してから送るなどの工夫が必要です。

補足

Tier5-03で学んだStateBagsと組み合わせることで、「同じバケット内のプレイヤーにだけ状態を同期する」といった、より高度な設計もできます(Tier5-09「StateBagsの応用パターン」で扱います)。
