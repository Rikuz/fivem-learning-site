StateBagsによる同期

結論

このレッスンを終えると、StateBags(エンティティやプレイヤーに紐づく、自動的に同期されるデータ領域)を使い、頻繁なイベント発火をせずにデータを共有することができるようになります。

説明

これまでのレッスンでは、データをclient/server間で共有するためにTriggerClientEvent/TriggerServerEventを使ってきました。しかし「プレイヤーが今どのJobか」のように、多くのclientが継続的に参照したいデータをイベントで送り合うと、通信回数が増えて非効率です。

StateBagはエンティティ(Ped/Vehicleなど)やプレイヤーに紐づく特別なデータ領域で、一度値を設定すると、関係するclientに自動的に同期されます。値が変わったことをイベントハンドラで検知することもできます。

コード例

Entity StateBag: エンティティにデータを持たせる

-- server.lua: NPCにカスタムデータを持たせて同期する
local ped = CreatePed(4, `a_m_m_business_01`, 100.0, 200.0, 30.0, 90.0, true, false)

Entity(ped).state:set('shopType', 'grocery', true)
-- 第3引数 true = 全clientに同期する(replicated)

Entity StateBag: client側で値を読む

-- client.lua
local shopType = Entity(ped).state.shopType
print('このNPCの店の種類: ' .. tostring(shopType))

Player StateBag: プレイヤーにデータを持たせる

-- server.lua
RegisterNetEvent('myscript:updateJob')
AddEventHandler('myscript:updateJob', function(jobName)
    local playerId = source
    Player(playerId).state:set('job', jobName, true)
end)

値が変化したときに反応する

-- client.lua: 誰かのjob状態が変化するたびに呼ばれる
AddStateBagChangeHandler('job', '', function(bagName, key, value, reserved, replicated)
    print(('%sのjobが%sに変わりました'):format(bagName, tostring(value)))
end)

注意点・よくあるミス

  • StateBagの値は基本的に誰でも読める(同期対象の全clientに配布される)ため、他人に見られたくない機密情報(パスワード相当のデータなど)を入れてはいけません。
  • Entity(ped).state:set(...)の第3引数(replicated)をfalseのままにすると、そのサーバー側でしか値が見えず、client側には同期されません。他clientでも参照したい場合は必ずtrueを指定してください。
  • StateBagは「多くのclientが継続的に参照する比較的静的なデータ」に向いています。1フレームごとに変わるような値(座標の詳細な動きなど)には、既存のネイティブな同期機構(エンティティの位置同期など)を使う方が適しています。

補足

StateBagsを使うと、「Jobが変わるたびに全clientへイベントを送って回る」ような処理を「値をsetするだけ」に置き換えられ、通信量とコードの複雑さの両方を減らせます。特に人数が多いサーバーほど効果が大きくなります。
