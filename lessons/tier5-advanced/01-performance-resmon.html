パフォーマンス計測と最適化

結論

このレッスンを終えると、resmonで自分のスクリプトの負荷を数値で確認し、Wait()の値を調整して負荷を下げるという、実運用で欠かせない最適化の基本ができるようになります。

説明

「なんとなく重い気がする」ではなく、どのresourceが・どれくらいCPUを使っているかを数値で確認することが最適化の第一歩です。F8コンソールのresmonコマンドがこれを表示してくれます。

コード例

resmonの使い方

resmon 1

F8コンソールで上記を実行すると、画面に各resourceのCPU使用率(ミリ秒/フレーム)の一覧が表示され続けます。数値が大きいresourceほど負荷が高いことを意味します。もう一度resmon 0を実行すると非表示にできます。

Wait()の値を見直す例

-- ⚠️ 見直し前: 常に毎フレーム(Wait(0))で座標を取得している
CreateThread(function()
    while true do
        local coords = GetEntityCoords(PlayerPedId())
        -- 何らかの判定処理
        Wait(0)
    end
end)
-- ✅ 見直し後: 用途的に毎フレームである必要がなければ、間隔を空ける
CreateThread(function()
    while true do
        local coords = GetEntityCoords(PlayerPedId())
        -- 何らかの判定処理
        Wait(500) -- 0.5秒ごとで十分なら、負荷はおよそ1/30程度になる
    end
end)

距離に応じてWait()を切り替える(頻出パターン)

CreateThread(function()
    while true do
        local playerCoords = GetEntityCoords(PlayerPedId())
        local distance = #(playerCoords - vector3(100.0, 200.0, 30.0))
        local waitTime = 1000

        if distance < 50.0 then
            waitTime = 200
        end
        if distance < 5.0 then
            waitTime = 0 -- 近くにいるときだけ毎フレームの精度で処理する
        end

        Wait(waitTime)
    end
end)

注意点・よくあるミス

  • resmonの数値はサーバーの状態(接続人数・他resourceの負荷)によって変動します。1回だけでなく、何度か時間を置いて確認しましょう。
  • 「とにかく全部のWait()を大きくすればいい」わけではありません。UI表示の追従性やマーカー表示の精度が必要な処理まで間隔を空けすぎると、プレイヤー体験が悪化します。用途に応じたバランスが重要です。
  • 負荷の原因がループのWait()ではなく、ループの中で毎回重い処理(大量データのループ処理や頻繁なDBアクセスなど)をしていることもあります。resmonで「重い」と分かったresourceは、中身のコードも確認しましょう。

補足

Tier2「スレッドとループ」で学んだWait()省略厳禁のルールと、このレッスンの「間隔を適切に空ける」は矛盾しません。「省略は絶対ダメ」「その上で、値をどれくらいにするかは用途に応じて調整する」という2段階で理解してください。
