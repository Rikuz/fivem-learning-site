非同期DB処理のパターン

結論

このレッスンを終えると、複数のDB処理を「順番に実行する必要があるもの」と「同時に実行してよいもの」に分けて設計し、コールバックのネストが深くなりすぎない書き方ができるようになります。

説明

Tier3で学んだMySQL.Async.*はコールバック関数で結果を受け取る非同期処理です。複数のクエリを連続で実行しようとすると、コールバックの中にコールバックを書く「コールバック地獄」になりがちです。FiveMのLuaにはMySQL.Sync.*という同期版の関数もありますが、これはその場で処理が止まってしまうため、多用するとサーバー全体が固まる原因になります。基本は非同期のまま、構造を整理して書きます。

コード例

❌ ネストが深くなる例

MySQL.Async.fetchAll('SELECT * FROM users WHERE identifier = @id', { ['@id'] = identifier }, function(user)
    MySQL.Async.fetchAll('SELECT * FROM vehicles WHERE owner = @id', { ['@id'] = identifier }, function(vehicles)
        MySQL.Async.fetchAll('SELECT * FROM properties WHERE owner = @id', { ['@id'] = identifier }, function(properties)
            -- 3段ネストになり、読みにくく修正しづらい
            print(#vehicles, #properties)
        end)
    end)
end)

✅ 直列化が必要な場合: 名前付き関数に分割する

local function loadProperties(identifier, vehicles)
    MySQL.Async.fetchAll('SELECT * FROM properties WHERE owner = @id', { ['@id'] = identifier }, function(properties)
        print(#vehicles, #properties)
    end)
end

local function loadVehicles(identifier)
    MySQL.Async.fetchAll('SELECT * FROM vehicles WHERE owner = @id', { ['@id'] = identifier }, function(vehicles)
        loadProperties(identifier, vehicles)
    end)
end

loadVehicles(identifier)

✅ 並列化してよい場合: それぞれ独立に実行し、揃ったタイミングでまとめる

local function loadPlayerData(identifier, onComplete)
    local results = {}
    local remaining = 2

    local function checkDone()
        remaining = remaining - 1
        if remaining == 0 then
            onComplete(results)
        end
    end

    MySQL.Async.fetchAll('SELECT * FROM vehicles WHERE owner = @id', { ['@id'] = identifier }, function(vehicles)
        results.vehicles = vehicles
        checkDone()
    end)

    MySQL.Async.fetchAll('SELECT * FROM properties WHERE owner = @id', { ['@id'] = identifier }, function(properties)
        results.properties = properties
        checkDone()
    end)
end

loadPlayerData(identifier, function(results)
    print(#results.vehicles, #results.properties)
end)

注意点・よくあるミス

  • 「vehiclesの結果を使ってpropertiesを絞り込みたい」のように片方の結果がもう片方の入力になる場合は直列化(順番に実行)が必要です。無理に並列化すると、まだ結果が届いていない変数を参照してエラーになります。
  • 逆に、互いに無関係なクエリを律儀に直列で書くと、無駄に待ち時間が伸びます。関係ないデータ取得は並列化してレスポンスを速くしましょう。
  • MySQL.Sync.*(同期版)は、サーバー起動時の初期化処理など「一度きりで、他の処理を止めても問題ない場面」に限定して使うのが安全です。プレイヤーの操作に応じた処理では使わないでください。

補足

oxmysqlにはPromiseベースのexport(exports.oxmysql:execute(...)など)も用意されており、環境によってはawaitスタイルでよりシンプルに書ける場合があります。導入しているoxmysqlのドキュメントを確認してみてください。
