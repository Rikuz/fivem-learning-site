メタテーブルで疑似クラスを作る

結論

このレッスンを終えると、Luaにはない「クラス」の概念を、メタテーブルを使って再現し、複数のインスタンス(実体)を持つオブジェクト指向的な設計ができるようになります。

こんな時に使う: 「プレイヤーオブジェクト」「ペットオブジェクト」のように、同じ構造・振る舞いを持つデータを何個も扱いたいとき。QBCoreのPlayer.Functions.〜のような書き方の裏側を理解したいとき。

説明

Luaにはクラスという言語機能自体はありませんが、メタテーブル(あるテーブルに対して「見つからないキーにアクセスされたときの挙動」等を定義する特別なテーブル)を使うことで、クラスのような仕組みを表現できます。特に__index(存在しないキーへのアクセス時に代わりに参照するテーブルを指定する)がよく使われます。

コード例

クラスの定義

Pet = {}
Pet.__index = Pet -- Petテーブル自身をメタテーブルとして使う

function Pet.new(name, hunger)
    local self = setmetatable({}, Pet) -- 新しいテーブルにPetのメタテーブルを設定する
    self.name = name
    self.hunger = hunger or 100
    return self
end

function Pet:feed(amount)
    self.hunger = math.min(100, self.hunger + amount)
    print((self.name .. 'の満腹度: %d'):format(self.hunger))
end

function Pet:isHungry()
    return self.hunger < 30
end

インスタンス(実体)を作って使う

local dog = Pet.new('ポチ', 50)
local cat = Pet.new('タマ', 80)

dog:feed(20) -- ポチの満腹度: 70
print(dog:isHungry()) -- false

print(dog.name, cat.name) -- ポチ タマ(それぞれ独立したデータを持つ)

__indexの仕組み(なぜこれで動くか)

-- dog:feed(20) は、実は dog.feed(dog, 20) の糖衣構文(コロン記法)
-- dogテーブル自体には feed 関数が存在しないため、
-- メタテーブルの __index (= Pet) を探しに行き、Pet.feed が見つかって実行される

注意点・よくあるミス

  • Pet.__index = Petを書き忘れると、setmetatableで作ったインスタンスからPetで定義した関数が見つからず、nilエラーになります。この1行は疑似クラスパターンの定型句として覚えておきましょう。
  • function Pet:feed(amount)のようなコロン記法は、暗黙的に第1引数selfを受け取ります。ドット記法(function Pet.feed(self, amount))と完全に同じ意味ですが、コロン記法の方が「このインスタンス自身のメソッド」であることが分かりやすくなります。
  • 複雑な継承(クラスを継承したクラス)を実現するには、さらに複数のメタテーブルを連結する必要があり、コードが読みにくくなりがちです。本当に必要な場合を除き、シンプルなテーブル+関数の組み合わせで十分なことも多いです。

補足

QBCoreのPlayer.Functions.AddMoney(...)のような書き方や、ESXのxPlayer.getMoney()は、まさにこのメタテーブルによる疑似クラスパターンで実装されています。フレームワークのソースコードを読むときの理解の助けになります。
