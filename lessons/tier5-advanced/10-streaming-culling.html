エンティティのストリーミング距離・カリング調整

結論

このレッスンを終えると、大量のNPC・オブジェクトを配置した際に、描画・処理の負荷を抑えるための距離設定(カリング)を調整できるようになります。

こんな時に使う: イベント会場に大量の装飾プロップを置いたら重くなった、多数のNPCを配置するショップ街を作ったら負荷が高いとき。

説明

カリング(視界に入らない、または一定距離より遠いオブジェクトの描画・処理を省略する最適化手法)は、ゲームエンジンが標準で行っていますが、その基準距離をスクリプトから調整できます。全てのエンティティが常に最大範囲で処理され続けると、Tier5-01で学んだ負荷の原因になります。

コード例

個別のエンティティのカリング距離を設定する

local prop = CreateObject(`prop_sign_advert_01a`, 100.0, 200.0, 30.0, true, true, false)

-- SetEntityDistanceCullingRadius(entity, radius)
-- 通常より近い距離(例: 30メートル)でカリングさせることで、遠くからの負荷を減らす
SetEntityDistanceCullingRadius(prop, 30.0)

大量のプロップを配置する際の工夫

local decorations = {
    { model = `prop_bunting_01`, coords = vector3(100.0, 200.0, 31.0) },
    { model = `prop_bunting_01`, coords = vector3(102.0, 200.0, 31.0) },
    -- ... 大量の装飾データ
}

local spawnedProps = {}

local function spawnNearbyDecorations()
    local playerCoords = GetEntityCoords(PlayerPedId())

    for _, decoration in ipairs(decorations) do
        local distance = #(playerCoords - decoration.coords)
        local key = decoration.coords.x .. '_' .. decoration.coords.y

        if distance < 50.0 and not spawnedProps[key] then
            -- 近づいたときだけ生成する(全部を最初から出しっぱなしにしない)
            local prop = CreateObject(decoration.model, decoration.coords.x, decoration.coords.y, decoration.coords.z, false, false, false)
            SetEntityDistanceCullingRadius(prop, 60.0)
            spawnedProps[key] = prop
        elseif distance >= 50.0 and spawnedProps[key] then
            -- 離れたら削除する
            DeleteObject(spawnedProps[key])
            spawnedProps[key] = nil
        end
    end
end

CreateThread(function()
    while true do
        spawnNearbyDecorations()
        Wait(2000)
    end
end)

注意点・よくあるミス

  • SetEntityDistanceCullingRadiusを極端に小さくしすぎると、プレイヤーが近づいているのに描画が間に合わず、オブジェクトが突然出現するように見えることがあります。用途に応じたバランスを取ってください。
  • 大量のエンティティを常時生成したままにするのではなく、上記コード例のように「近づいたら生成、離れたら削除」という動的な管理をすることで、根本的な負荷を大きく減らせます。カリング距離の調整と組み合わせるとさらに効果的です。
  • この最適化はclient側の処理です。server側で大量のエンティティのネットワーク同期(isNetwork = true)を行っている場合は、サーバー全体の負荷にも影響します。装飾のように他プレイヤーと共有する必要のないものは、isNetwork = falseのローカルエンティティにすることも検討してください。

補足

このレッスンで扱った「近づいたら生成、離れたら削除」というパターンは、Tier2-03のBlip/Marker表示制御や、Tier2-11のパーティクルエフェクトの管理でも繰り返し登場した考え方です。FiveMスクリプト開発全体を通じて、この「距離に応じた動的な管理」は非常に重要な最適化テクニックです。
